把 Agent 的判断变成可验证证据

这是自研 Agent 评估项目的设计原型。当前已经明确任务契约、证据边界、评估维度和实现顺序；尚未接入真实仓库执行、Trace 采集与证据投影，因此页面不会生成或展示虚假的运行评分。

这里解决什么问题这是自研评估项目的设计入口：先定义任务和证据，再开发隔离执行、Trace、回归与报告。评分器本身尚未上线。

评估契约

先建立被评测 Agent 的画像，再选择与任务相称的证据。不同任务不共享一张“万能评分表”。

任务契约目标、输入、允许副作用、成功条件、失败条件与预算。输入事实
执行轨迹模型调用、工具参数、状态迁移、重试、权限和时间线。过程事实
结果证据产物、测试、数据库状态、引用、用户目标和可复现记录。结果事实
判断把观察到的事实映射到任务特定的质量标准。解释层
改进给出最小改变、作用机制、成本、风险和回归方案。行动层
回归把改进写回固定任务集，比较前后结果与失败类型。持续层

框架只守住事实边界，语义判断由 Agent 或评审者完成。

计划接入的评估产物

下面是实现时的最小数据契约，先固定证据形状，再接入具体 Agent、仓库和任务夹具。

产物 必须回答 不能替代
Agent 画像 任务类型、模型、工具、状态、权限、依赖和版本。 不能由 README 单独证明运行行为。
任务夹具 输入、环境、成功/失败条件、预算和可重放步骤。 不能用模糊“看起来完成”作断言。
Trace 每次决策、工具调用、参数、返回、状态和时间。 不能把模型文本当作命令已执行。
证据包 日志、退出码、diff、测试、产物、引用和环境摘要。 不能隐去失败、重试或后一次覆盖前一次成功。
改进报告 问题、作用机制、最小改动、反例、成本、置信度和回归。 不能脱离证据编造性能或适用性。
