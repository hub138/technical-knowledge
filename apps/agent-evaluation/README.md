# Agent 评估原型（用于评估 Agent）

这个应用做的是一件事：评估 Agent。它把 Agent 的输出判断绑定到命令、日志、产物和测试，
让"这次 Agent 到底有没有做对"变成可核验证据，而不是一句主观结论。

它不属于 `projects/` 下的第三方开源项目，是这个仓库里维护的原型。`index.html` 当前展示评估契约、证据链、任务维度和计划接入的产物；它还是设计与导航原型，在接入真实执行前不会伪造某个 Agent 的运行结果。

## 设计依据

完整的评估契约已经写入：

`vault/工程知识/AI 系统工程/质量与运营/Agent评估系统的设计契约.md`

核心边界是：模型负责项目理解、方案选择和失败分析；运行时负责隔离、执行、日志、退出码、产物、任务代际和事实一致性。评估报告只能读取经过校验的证据投影。

## 历史页面

`legacy.html` 和 `legacy_server.py` 保留原仓库的静态知识/评估页面与旧启动方式，便于对照迁移；它们不是当前入口，也不应继续扩展。

## 当前成熟度

- 已有：评估设计契约、静态交互原型、与框架无关的 `agent-foundation` 基础包。
- 未有：真实仓库/任务接入、隔离执行器、统一 Trace schema、证据投影与可重放回归。
- 因此当前页面只能解释“准备怎样评”，不能回答“某次 Agent 运行得分多少”。

## 后续实现

先固定任务夹具和 Trace schema，再接入独立 worktree、进程组、凭据范围、证据包和回归投影；最后再接入模型评审、成本/SLO 和图谱。具体评估必须绑定目标仓库、提交、任务输入和可复现环境。
