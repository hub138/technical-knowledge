# Agent 的能力来自工具集，不来自模型

## 背景：换了个更强的模型，什么都没变

一个内部 Agent 表现平平。团队升级到最新最强的模型，期待明显改善。

结果：**几乎没有变化。**

复盘发现，它的失败集中在：

- "不知道项目里有哪些约定" → **没有能读 `AGENTS.md` 的工具**
- "改完不知道对不对" → **没有能跑测试的工具**
- "找不到相关代码" → **没有符号索引，只有全文 grep**
- "反复猜 API 签名" → **没有能查类型定义的工具**

**模型很强，但它手上什么工具都没有。** 就像一个很聪明的人被关在没有书、没有电脑、没有纸笔的房间里。

## 方案：能力清单 = 工具清单

### 先列出"人要完成这个任务需要什么"

不要从"模型能做什么"出发，**从"人做这件事需要什么信息/能力"出发**。

代码任务，一个工程师需要：

| 需要 | 对应工具 |
| --- | --- |
| 看代码 | `read_file`、`list_dir` |
| 找符号定义/引用 | **符号索引（LSP/AST）** |
| 搜索文本 | `grep` |
| 运行测试 | `run_tests` |
| 看报错 | 上一条的返回值 |
| 查项目约定 | 读 `AGENTS.md` |
| 看历史 | `git log`、`git blame` |
| 看类型定义 | `go doc`、`tsc` 或 LSP hover |

**每缺一个工具，Agent 就多一类失败。**

### 三类工具，优先级不同

**第一类：读的能力（最高优先级）**

没有读的能力，Agent 只能瞎猜。**优先保证**：

- 读文件（带行号）
- 搜索（关键词 + 语义）
- 符号跳转（定义/引用）
- 读项目约定文档

**第二类：验证的能力（第二优先）**

能读但不能验证 = 只能输出"看起来对"的东西。

- 跑测试
- 类型检查
- lint
- 编译

**验证能力是"能写代码"和"能交付代码"的分界线。**

**第三类：写的能力（最后）**

写的能力最容易给，也最危险。加写工具时**必须同时考虑**：

- 权限边界（能写哪些路径）
- 可逆性（有 git 就能回滚）
- 验证（改完能跑测试吗）

### 工具质量 > 工具数量

两个 Agent，一个有 20 个粗糙工具，一个有 6 个精心设计的——**后者通常表现更好**。

判断工具质量：

| 检查项 | 好的工具 |
| --- | --- |
| 描述清晰 | 模型知道何时用、何时不用 |
| 返回精简 | 不撑爆上下文，大内容给引用 |
| 错误可行动 | 失败时告诉模型下一步能做什么 |
| 幂等 | 重试不会造成副作用 |
| 权限受限 | 只能访问该访问的范围 |

### 加工具前先问三个问题

1. **没有它，Agent 会怎么失败？** —— 答不上来就别加
2. **人完成这个任务会用这个工具吗？** —— 不用，说明方向错了
3. **出错时能造成多大破坏？** —— 决定权限和是否需要人工确认

## 效果与代价

**收益**

- **能力提升最直接**：加对工具的效果常常比换模型更明显
- **可诊断**：失败能归因到"缺什么能力"
- **可累积**：工具集是资产，换模型时工具集还在

**代价**

- **每个工具都要维护**：描述、权限、错误处理、测试
- **工具多会稀释注意力**：超过 15-20 个，模型选择准确率下降
- **写工具有风险**：权限设计错了会造成破坏
- **工具依赖外部环境**：跑测试需要能跑起来的测试环境，这本身可能是工程量

## 从什么地方做

**第一步：手工完成任务 10 次，记录用到的每个动作**

这是唯一可靠的方法。**看自己实际用了什么，那就是工具清单。**

**第二步：检查现有工具集缺什么**

对照清单，找出"人会做但 Agent 做不到"的。**这些缺口就是失败来源。**

**第三步：优先补"读"和"验证"**

在加写能力之前，先让 Agent 能**看清**和**验证**。这两类工具风险低、收益大。

**第四步：给每个工具写清描述和边界**

见 [[Agent技能/工具与契约/工具契约决定Agent能做什么]]。

**第五步：定期删除没人用的工具**

记录每个工具的调用次数。**连续一个月没被调用的工具，要么描述有问题，要么根本不需要。**

## 常见错误

**错误 1：认为换模型能解决能力问题**

模型是"大脑"，工具是"手和眼"。**眼睛看不见，大脑再聪明也没用。**

**错误 2：只给写工具，不给验证工具**

能改代码但不能跑测试 → Agent 会输出未经验证的代码，并声称"已完成"。

**错误 3：工具返回太大**

`run_tests` 返回 3 万行日志，撑爆上下文。**返回摘要 + 引用。**

**错误 4：工具权限过宽**

给了通用 shell 访问 → 能做的事很多，能闯的祸也很多。**最小权限。**

**错误 5：工具集一次性给全**

20 个工具同时注入，模型选择困难。**按场景分组，动态加载。**

**错误 6：工具的失败不告诉模型原因**

返回 `"error"` → 模型只能重试同样的动作。**错误信息必须可行动。**
