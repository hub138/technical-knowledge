# 接口设计决定调用方会不会用错

## 背景：那个传错参数导致资损的接口

一个转账接口：

```
POST /transfer
{ "from": "A", "to": "B", "amount": 100 }
```

上线三个月后出现资损：有人把 `from` 和 `to` 写反了，钱转反了方向。代码 review 没发现，因为**两个参数类型一样、顺序也一样**，写反了看起来完全正常。

这不是调用方粗心。**是接口设计让这个错误变得容易发生。**

好的接口设计有个标准：**调用方想犯错都难**。这比"文档写清楚"可靠得多——文档会被跳过，类型系统不会。

## 方案：用设计消除整类错误

### 1. 让非法状态无法表示

**问题**：`{"from": "A", "to": "B"}` 允许表达"从 A 转到 A"这种无意义操作。

**改法**：把方向变成类型。

```go
type Transfer struct {
    Source      AccountID
    Destination AccountID
    Amount      Money      // 不是 int64
}
```

`Money` 是独立类型（含货币单位），`AccountID` 也是。**转账金额传成字符串会编译不过。**

### 2. 明确单位，把单位写进名字或类型

`amount: 100` —— 是分还是元？是 100 元还是 100 分？**这个歧义造成过大量线上事故。**

三种改法，按可靠程度：

| 改法 | 例子 | 可靠性 |
| --- | --- | --- |
| 单位进字段名 | `amount_cents: 10000` | 中（靠人读） |
| 单位进类型 | `Money{Value: 100, Currency: "CNY"}` | 高（编译期） |
| 用最小单位 + 明确约束 | `int64` 分，且 schema 校验范围 | 中高 |

**优先选类型。**

### 3. 必填和可选要能用类型区分

```go
// 差：零值代表"没提供"还是"提供了 0"？
type UpdateUser struct {
    Name  string
    Age   int
}

// 好：用指针或 Option 明确区分
type UpdateUser struct {
    Name  *string
    Age   *int
}
```

**"零值语义"是 Go 里最常见的接口陷阱**：`Age: 0` 到底是"把年龄改成 0"还是"不改年龄"？分不清就会写出 bug。

### 4. 幂等键放进接口，而不是靠文档

```http
POST /payments
Idempotency-Key: <client-uuid>    ← 必需，缺失则 400
```

把幂等设计成**接口的一部分**，调用方必须提供。这样重试就是安全默认值。

### 5. 分页用游标，不用 offset

```http
# 差：offset 在数据变动时会漏数据、重复数据
GET /items?offset=100&limit=20

# 好：游标锚定在具体位置
GET /items?cursor=eyJpZCI6MTIzfQ&limit=20
```

`offset` 的问题：第 1 页读完，有人删了 5 条，第 2 页就跳过了 5 条记录。

## 效果与代价

**收益**

- **整类错误消失**：类型系统挡住了参数顺序、单位混乱、非法状态
- **文档需求减少**：接口自解释时，调用方不需要读那么多文档
- **重构安全**：改字段类型时编译器会找出所有需要改的地方

**代价**

- **更多类型定义**：`Money`、`AccountID` 这些包装类型要写转换方法
- **序列化复杂度**：自定义类型需要实现 Marshal/Unmarshal
- **过度设计的风险**：给每个 `string` 都包一个类型会让代码臃肿。**只对"容易混淆"和"有业务约束"的字段做**

## 从什么地方做

**第一步：找出所有"同类型相邻参数"**

搜函数签名，找连续两个以上同类型参数的地方：

```go
func Transfer(from, to string, amount int64, currency string)
```

**同类型参数相邻 = 调用方可以静默传反。** 这是最该优先改的。

**第二步：给所有金额加单位**

检查所有涉及金额、时间、大小的字段：名字里有单位吗？是 `int` 还是包装类型？**金额永远不用裸 `int`。**

**第三步：检查零值歧义**

对每个更新类接口，问：零值是"不修改"还是"改成零"？如果是后者，用指针或 `Optional`。

**第四步：把幂等键做成必需参数**

所有写接口加 `Idempotency-Key`（或业务上的唯一标识），缺失时返回 `400` 而不是静默接受。

**第五步：用契约测试锁住**

生成客户端 SDK 或写 schema 校验测试。**接口变更时让契约测试失败**，而不是等到调用方线上炸。

## 常见错误

**错误 1：用 `bool` 做多态开关**

`func Get(id string, includeDeleted bool)` —— 加第三个选项时就要再加一个 bool。**用 enum 或 option 结构。**

**错误 2：把 HTTP 状态码当业务状态码用**

用 `200` 返回 `{"error": "余额不足"}`。这让监控、重试、熔断都无法工作。**业务失败用 `4xx`，系统失败用 `5xx`。**

**错误 3：让调用方拼 URL**

```
GET /users?filter=status%3Dactive%26age%3E18
```

调用方要自己拼查询语法，容易注入且难维护。**用明确的查询参数。**

**错误 4：返回值里塞 `map[string]interface{}`**

调用方不知道有什么字段，必须看文档或猜。**用明确的 struct。**
