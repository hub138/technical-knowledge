# SSD与HDD的IO特性差异：随机写与写放大

## 要解决的问题

SSD 与 HDD 的特性差异要回答的问题，是**为什么"换块盘"不能只看容量与顺序吞吐**。HDD 的性能模型是机械的：磁头移动（寻道）+ 盘片旋转（旋转延迟），随机访问的代价是物理距离。SSD 没有机械部件，随机读几乎与顺序读一样快——但它有自己的一套隐藏成本：擦写块（erase block）、写放大（write amplification）、垃圾回收（GC）。数据库与存储引擎的选型（顺序写 vs 随机写、B树 vs LSM 树）全部建立在这套差异上。不理解盘，就理解不了存储引擎为什么长那样。

## 机制

**HDD：机械模型，随机即惩罚**。一次 IO = 寻道（平均几 ms）+ 旋转延迟（平均几 ms）+ 传输（微秒级）。顺序 IO 的寻道摊薄到零，所以 HDD 的顺序吞吐（100-200 MB/s）与随机 IOPS（100-200，4KB 块）差三个数量级。**HDD 的设计信条是"把随机变顺序"**：数据库的预写日志、排序合并、电梯算法（IO 调度器），全是为了把随机写聚成顺序流。

**SSD：电子模型，但写前必须擦**。闪存的物理约束：写（program）只能把 bit 从 1 改 0，要改回 1 必须先擦（erase）；擦的单位（erase block，几 MB）远大于写的单位（page，几 KB）。**不能原地改写**是所有麻烦的源头。SSD 控制器用 FTL（flash translation layer）把这个丑陋的物理藏起来：逻辑块地址（LBA）映射到物理页，改写一个 4KB 逻辑块 = 写新物理页 + 改映射表 + 旧页标记失效。对上层呈现"可随机写的块设备"的假象。

**写放大：4KB 的写背后是几倍的物理写**。垃圾回收要回收失效页：把含失效页的 erase block 里的有效页搬走（读+写），再擦整块。搬移是额外物理写，不产生任何逻辑收益。写放大 WA = 物理写量 / 逻辑写量，稳态 1.5-3x，GC 压力大时 10x+。写放大的直接后果：SSD 的实际写入带宽与寿命（P/E 循环次数）被 WA 吃掉一块，"标称 500MB/s 写入"在随机小写稳态下可能只剩三分之一。

**两个由此派生的工程要点**。一是 TRIM/DEALLOC：上层告诉 SSD"这些逻辑块不要了"，SSD 把对应物理页标记可回收，GC 不用搬死数据，WA 下降。文件系统与数据库要正确发 TRIM（丢弃已删文件、已删页）。二是预留空间（OP，over-provisioning）：留一部分物理容量不给上层（7%-28%），GC 的腾挪余地变大，稳态 WA 下降、延迟抖动收窄。企业级 SSD 的 OP 更大，贵有贵的道理。

## 背景与代价

思想背景：HDD 的机械模型统治了 50 年（1956 年 IBM RAMAC 起），存储引擎的全部设计惯性（顺序写、大块 IO、减少寻道）都是对机械的妥协。闪存商业化（1990s 末期，东芝发明闪存是 1980）初期照搬 HDD 的接口（块设备），FTL 是这个"新物理装旧接口"的过渡层——它成功了，成功到多数软件完全没意识到底层物理已经换了。LSM 树（1996 论文）的复兴（2000s 后半，Bigtable/RocksDB 时代）是对 SSD 特性的响应：LSM 把随机写变成顺序写的设计在 HDD 时代为了寻道，在 SSD 时代换了一个理由——顺序大块写让 FTL 的 GC 更友好（整段回收，少搬移），WA 更低。LSM树把写放大变成可控的工程参数（见 [[工程知识/数据系统：在并发与故障中保存事实/事务与存储/LSM树用写放大换取顺序写和可扩展性.md]]）写的是软件层的 WA，本文补硬件层的 WA，两层 WA 相乘才是全貌。

最精巧的一笔是**FTL 把"物理不可改写"翻译成"逻辑可改写"**。这个翻译层让五十年积累的软件生态（文件系统、数据库、一切假定块设备的软件）零改动跑在新物理上。代价要摆明：翻译有损——上层看不到物理真相，WA 的存在让上层性能模型失真（写入带宽的抖动、延迟毛刺来自 GC 的时机不可控）；物理真相被藏也让寿命管理（P/E 耗尽）对上层不可见，SSD 的磨损是缓发的死亡，监控要读 SMART 的磨损指标（见 [[工程知识/数据系统：在并发与故障中保存事实/可靠性与运维/备份恢复是可验证的时间边界.md]]）而不是等它坏。

## 边界

- **SSD 的随机读快，不等于随机读免费**。4KB 随机读的 IOPS（几十万）远超 HDD，但顺序读仍高数倍吞吐（预读、少映射查询）。读路径的优化（局部性、大块）在 SSD 上收益缩小但没消失。ECC 内存把单比特错误挡在报告之前（见 [[工程知识/性能工程：从用户等待到资源瓶颈/处理器与内存/ECC内存把单比特错误挡在报告之前.md]]）是数据可靠性的另一环：位翻转在存储与传输路径都可能发生，ECC 是内存侧的防线。
- **性能抖动是 SSD 的常态不是故障**。GC 的触发时机、磨损均衡的搬移、SLC 缓存的用尽，都会造成 P99 延迟毛刺。用 HDD 时代的"稳定吞吐"预期看 SSD 会误判；SSD 的容量与写入历史（盘的"脏"程度）改变性能曲线，压测前要 prefill 到稳态。
- **企业盘与消费盘的差距在 OP 与电容**。断电保护（电容给 FTL 落映射表的时间）、大 OP、更严的筛选，企业盘的写入可靠性与 QoS 好于消费盘。数据库场景用消费盘省的钱，可能加倍付给数据恢复。
- **HDD 没死，冷数据的容量经济还在**。SSD 的 $/TB 仍数倍于 HDD，对象存储与备份池的底层仍是 HDD（叠瓦式 SMR 进一步压容量成本，代价是改写惩罚更狠）。存储分层（热 SSD、温 HDD、冷磁带/对象）是成本与性能的常规解，见分层思想在存储栈的贯穿。

## 验证

- **随机与顺序的差距实测**：fio 对同一盘跑 4KB randwrite 与 1M seqwrite，预期：HDD 上 seq 吞吐/rand IOPS 差三个数量级；SSD 上差距收窄到几倍（读路径），写路径受 WA 影响稳态值波动。结果与预期差一个量级，先查测试方法（队列深度、是否绕过页缓存 direct=1）。
- **写放大观测**：读 SMART 的 Host Writes 与 NAND Writes（部分盘暴露），预期：稳态随机写场景 NAND/Host 比 1.5-3；比值随盘内空闲空间减少而上升（OP 被填，GC 搬移变多）。盘不暴露 NAND 计数时，用延迟毛刺频率做间接信号。
- **TRIM 效果验证**：填满盘 → 删一半文件（发 TRIM）→ 重跑随机写，预期：TRIM 后的写延迟与吞吐显著好于不 TRIM 的对照组（GC 有干净块可回收）。对照组差异即 TRIM 价值的直接证据。
