# 重建只改配置不改数据：放置策略变更要配套重平衡

> **要点**：副本放置策略（机架感知、磁盘权重）只约束"新数据的放置"，存量数据的分布是策略变更时点之前的历史——配置改完就当"已完成"是自欺，策略变更的完整动作是改配置 + 评估存量偏离 + 必要时触发重平衡（带限速与窗口）；上游"region aware placement policy disk weight not update"的缺陷正是策略读的是旧权重快照，配置层与放置层的同步缺口。

## 要解决的问题：配置生效与策略生效的时间差

放置策略在两个时点起作用：**写路径**（每个新副本按当前策略选位置）、**读路径**（ensemble 映射决定从哪读）——策略变更瞬间生效的是写路径，**存量副本的位置不会因配置变化而移动**。这个"只对增量生效"的性质是副本系统的一般规律（K8s 的调度策略、HDFS 的 placement、副本云盘的 AZ 约束同理），却总被"改了配置就完事"的操作惯性掩盖。本库"热点副本与流量倾斜"篇讲过倾斜的治理；本篇聚焦**策略变更的操作协议**：变更不只是写配置，是"改配置 + 存量评估 + 重平衡决策"三步。

## 机制：三步协议

**第一步：改配置并验证生效面**。配置变更后核对两件事：写路径真的用新策略（新写入的副本位置抽查符合新规则）；策略引擎读的权重/拓扑**没有缓存旧值**——上游 disk weight not update 的缺陷就在这一步：region-aware 策略读取的磁盘权重是注册时的快照，控制台改了权重、策略引擎用旧快照，"配置生效"与"策略生效"分离。**验证方法**：打标验证（提交一批探针写入，检查副本位置分布是否符合新权重）——配置中心的确认界面说"已生效"，探针写入的实际位置才是事实（本库"地图与地盘"的纪律：行为验证先于界面确认）。

**第二步：存量偏离评估**。新策略上线后算一笔账：存量数据的分布与新策略的目标分布差多少——**偏离度量化**（按机架/磁盘的副本数对比目标比例，最大偏离与偏离的副本量），评估结果决定第三步做不做、做多快。**偏离的代价要具体化**：机架倾斜的代价是故障域风险（一个机架挂掉丢的副本超预算）、磁盘权重失衡的代价是容量与 IO 的热点（本库"数据分布不均"的机制层）——代价重的偏离才值得动重平衡（重平衡本身是 IO 大户）。

**第三步：重平衡带限速与窗口**。决策做重平衡后，三个参数控制它的破坏力：**限速**（每秒迁移副本数/字节数，按业务低峰的前台 IO 余量倒推，本库节流参数篇的同类核算）、**窗口**（低峰时段执行，超窗暂停）、**顺序**（先迁故障域敏感的副本还是先迁容量敏感的，按评估出的主要代价定）。**重平衡的中断安全**：迁移中的副本有中间态（源已删目标未齐），进程重启后要能续跑——重平衡任务的断点记录是必需件，不是可选项。

## 看完能判断：策略变更的检查单

**变更前**：新策略的探针验证方案备好；存量偏离评估的脚本备好（变更后立即出数）；重平衡的限速值按低峰 IO 余量算好。**变更时**：配置改完跑探针（副本位置分布符合新权重才继续）；观察一个写入周期（新副本的 ensemble 抽查）。**变更后**：评估报告出数（最大偏离与副本量）；决定重平衡的启动窗口；重平衡期间盯两个水位（迁移限速的执行率、前台的延迟水位——限速过紧迁移拖长，过松前台抖动）。**回退路径**：策略改回旧值同样只对增量生效——重平衡做到一半回退，已迁的副本不回迁（回迁是第二轮重平衡的事），**回退的语义是"停止增量"，不是"恢复原状"**——操作者对这个语义的误解是二次事故的来源。

**多策略共存的集群**：新旧策略交接期内，存量按旧策略、增量按新策略——**交接期是常态而非异常**（重平衡以天计），监控面板按策略版本分列副本分布，"看起来乱"的混合态有账可查就不慌。

## 边界

三条边界防止防线走形。

**重平衡不是策略修复的唯一手段**：轻微偏离（故障域风险在预算内）可以不动——重平衡的 IO 成本与风险（迁移期的副本数暂时不足）要小于偏离的代价才做，**"分布完美"不是目标，"风险在预算内"才是**。

**容量约束先于策略约束**：新策略（如要求跨三机架）遇到机架容量不足时无法满足——放置策略的可行性受拓扑容量约束，策略变更前核拓扑容量（目标机架的剩余空间装得下要迁入的量），装不下的策略是纸面策略。

**权重是策略的输入不是装饰**：磁盘权重影响新写入的副本位置概率，权重设置要与磁盘的实际容量/性能匹配（大盘高权重）——上游缺陷的教训反向成立：权重可改，改完要有验证它进入策略计算的路径。

## 验证

可复现的验证路径：

1. 生效面复现：改权重后打标探针写入，预期副本位置分布向新权重收敛（卡方检验或比例对比）；
2. 评估脚本验证：构造已知偏离的集群拓扑，评估脚本输出的偏离量与构造值一致；
3. 重平衡演练：低峰窗口小规模迁移（限速下），验证限速执行、断点续跑、前台延迟无感；
4. 断言锚点：**策略变更有探针验证、存量偏离有评估报告、重平衡带限速窗口与断点**——三件齐备，策略变更从"改配置"升级为"改配置加核账加搬迁"的完整操作。

```text
生效断言 = 探针副本位置验证策略真生效
评估断言 = 存量偏离有量化报告
搬迁断言 = 重平衡限速续跑可中断
```

放置策略的变更协议核心是承认时间性：配置支配增量，存量欠账要靠评估与重平衡偿还——探针验证让"生效"有事实依据，偏离评估让重平衡有决策依据，限速与断点让搬迁不伤前台，三步走完策略变更才算闭环。
