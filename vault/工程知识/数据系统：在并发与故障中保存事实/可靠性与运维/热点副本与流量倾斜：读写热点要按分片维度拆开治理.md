# 热点副本与流量倾斜：读写热点要按分片维度拆开治理

> **一句话总结**：倾斜的治理入口是分片键与放置策略——写热点靠分片键打散与二次随机化，读热点靠副本放置与本地化调整，热门单键（大 V、爆款）超出分片能力时靠应用层缓存与拆分；"均匀分片但流量倾斜"与"分片倾斜"是两种病，诊断先分清再开方。

## 要解决的问题

分布式存储的容量线性扩展依赖一个前提：**负载在分片间均匀**。现实经常违背这个前提——某几个分片的磁盘、网卡、CPU 长期满载，其余分片闲着，集群容量利用率看着健康（平均 40%），实际已经在热点分片上排队。本库后端域"数据分布不均让分片失去意义"讲过倾斜的机制根源；本篇回答治理端：**倾斜的两种形态（分片倾斜与访问倾斜）各自的诊断信号与治理手段**——手段用错方向（用加节点治分片倾斜），扩容的钱花出去，热点还在原地。

## 机制：两种倾斜的诊断与治理

**分片倾斜（数据分布的问题）**：分片键选择不当（按时间戳、按递增 ID 顺序写），写入集中在最新分片——诊断信号是**各分片的数据量与写入速率的分布**（P90 分片与 P10 分片的比值，持续大于 3 即倾斜）。治理手段按根源选：分片键改成散列（写入按哈希摊开，代价是范围查询失效）、复合键加随机前缀（写入打散，读取端聚合）、分片数与写入并行度重新匹配。

**访问倾斜（流量分布的问题）**：数据分布均匀，但某些键的访问量天然集中（热门用户、爆款商品）——诊断信号是**单键的读写 QPS 分布**（Top 键占比）。治理手段按读与写分别开方：**读热点**靠副本放置（热门键的副本分散到多节点，客户端轮询读）与应用层缓存（热门读不落到存储层）；**写热点**靠分片内聚合（批量提交摊平单键写放大）、异步化（写延迟容忍的场景转异步队列），单键写热点超出一切存储手段时（每秒数万次写同一个键），靠应用层拆分（按子键分桶、按时间分片）。

**两者叠加的形态**：分片倾斜 + 访问倾斜的热点分片是容量事故的高发区——治理顺序先治分片倾斜（分布正常后访问倾斜的量级才看得清），再治访问倾斜。**一次只动一个变量**：同时改分片键与缓存策略，倾斜缓解的归因无从判定。

## 看完能判断：治理手段的选择树

**第一问：倾斜在分片间还是键间？**分片间的数据/流量分布不均 → 分片倾斜，治理在分片键与再平衡；分片均匀但单键流量集中 → 访问倾斜，治理在副本放置与应用层。**诊断的数据基础是分片级与键级两套统计**，只有集群总量的监控看不出任何一种倾斜。

**第二问：热点是稳定的还是轮动的？**稳定热点（固定的热门键）→ 长期手段（缓存、副本放置）一次配好；轮动热点（今天的爆款与明天不同）→ 自动化手段（热点检测 + 自动副本迁移），上游 BookKeeper 的 region-aware 放置策略按磁盘权重分配写流量的改进正属此类——**轮动热点的治理必须是自动的**，人工响应追不上轮动周期。

**第三问：热点键能否拆分？**键的业务语义允许拆（会话、订单可以按子键分桶）→ 应用层拆分治本；不允许拆（单条记录的计数器）→ 聚合与异步治标，容量按热点峰值单独预算。

## 边界

三条边界防止防线走形。

**缓存引入自己的热点形态**：热门键缓存失效的瞬间（缓存击穿），存储层承受全部读流量——**热点键的缓存续期与互斥重建**（只放一个请求回源）是缓存方案的必要配套，不带配套的缓存把读热点变成读脉冲。

**打散与顺序的交换要业务确认**：随机前缀打散写入，同时破坏同键写入了顺序保证——**键的顺序语义在打散前要跟业务核对**（消息按 key 分区保序是常见的隐藏依赖），打散不能破坏业务依赖的顺序。

**热点治理的度量在客户端不在服务端**：服务端看热点分片的负载，客户端看请求延迟的分布——治理效果以客户端 P99 的收敛为准，服务端负载均匀但客户端延迟没降，说明瓶颈在别处（网络、客户端自身）。

## 验证

可复现的验证路径：

1. 倾斜复现：构造顺序键写入与热门单键访问两个场景，预期分片统计与键统计分别呈现两种倾斜形态——诊断信号与形态对得上；
2. 治理验证：打散分片键后写入分布的 P90/P10 比值收敛；热门键加副本放置后客户端读延迟收敛；
3. 击穿防护验证：热门缓存失效瞬间，存储层读流量预期被互斥重建限制在单请求量级；
4. 断言锚点：**分片级与键级两套统计在管、倾斜比值有基线、治理效果以客户端 P99 判定**——三件齐备，倾斜从"偶尔的容量事故"变成"有指标的持续治理"。

```text
诊断断言 = 两套统计能区分两种倾斜
治理断言 = P90/P10 与客户端 P99 双收敛
防护断言 = 击穿瞬间回源被互斥限制
```

倾斜治理的路径从诊断开始：先分清两种病，再按稳定性与可拆性选手段——顺序对了，每一步的投入都落在瓶颈上。
