# 批处理与流处理的取舍：时序语义与一次性投入决定路径

> **要点**：批与流的差异不在数据量，在两条轴——时间语义（结果是否随处理时间漂移）与一次性投入（幂等基建与运维体系）；存量覆盖了各自的时间语义机制，本篇补齐选择路径：按时序要求与运维代价定路径，按可重放与幂等定保障。

## 要解决的问题与本质：批与流是同一计算的两条执行路径

同一份聚合逻辑（按窗口统计事件数）可以两种方式执行：攒一天数据一次性算（批），或者事件到达即增量算（流）。工程团队在这里面对一个真实问题：两种执行方式的基建投入、结果语义、运维代价差异巨大，选错路径的项目要么买了用不起的实时性、要么缺了要命的新鲜度。本库数据系统域"批处理与流处理共享逻辑但不共享时间语义"讲过核心分界——**时间语义是流处理的灵魂：事件时间（事件发生时刻）与处理时间（处理发生时刻）的偏差不可消除，窗口归属、乱序容忍、水位线机制全部围绕它展开**；本篇回答工程决策端的另一半：**什么时候值得上流处理，什么时候批处理是更诚实的答案**。

本质层面，批与流的取舍结构可以用两组问题收拢：**结果的新鲜度要求**（分钟级延迟可接受，还是秒级必须）与**结果的确定性要求**（同一输入重复执行结果是否相同——批天然确定，流要靠水位线与幂等基建争取）。两条轴正交：低延迟 + 可确定的结果，才是流处理的完整理由；只占一条，批处理或半批半流（微批）通常更便宜。

## 机制：时序语义的三个构件

**事件时间 vs 处理时间**：窗口按哪个时间轴切分，决定结果的业务含义——按事件时间统计"昨天全天下单量"，离线补算结果稳定；按处理时间统计，同一天的数据在不同时刻算出不同结果（受延迟与积压影响）。**选错时间轴的统计结果是"看起来能对"的错数据**，这种错不会报错，只在业务方核对时暴露。

**水位线与乱序容忍**：事件时间处理必须回答"等到什么时候才认为某窗口的数据到齐"——水位线是"当前事件时间进度"的估计，水位线超过窗口终点即触发计算；迟到数据按 allowLateness 策略补算或丢弃。**水位线是权衡的旋钮：等得久则结果准但延迟高，等得短则延迟低但迟到数据多**，旋钮的设定依据是上游事件延迟的分布（P99 延迟 + 安全余量）。

**恰好一次的支撑结构**：流的"恰好一次"由三层叠出来——可重放的源头（Kafka 按偏移量重放）、幂等的汇（按主键 upsert 或事务写入）、一致的检查点（状态快照与偏移量原子提交）。**缺任何一层，故障恢复后要么丢数据要么重复计数**；这层的基建投入与运维复杂度（检查点调优、反压治理、状态后端运维）是流处理的真实价格。

## 看完能判断：路径选择与保障配置

**路径选择的判定顺序**：第一问新鲜度——小时级可接受则批（最便宜、最可确定、可重跑）；分钟级则微批（批的基建 + 流的新鲜度折中）；秒级必须才流。第二问确定性——流路径上核对三层恰好一次基建是否齐备，缺层则按"至少一次 + 幂等汇"降级设计并显式接受。**两问都是"否"却上了流处理的项目，买到的是最贵的结果不确定**。

**批路径的保障**：可重跑（同一输入重跑结果相同）依赖输入快照与确定性逻辑——输入用不可变快照（分区路径带日期），逻辑避免"当前时间"类随机源；**批任务的可重跑性等价于流任务的恰好一次，都是确定性保证，验证方式同源**（重跑对账）。

**流路径的保障清单**：源头可重放（偏移量管理）、窗口按事件时间、水位线按延迟分布调参、汇幂等（主键 upsert）、检查点与恢复演练（本库可靠性与运维域"备份的价值由恢复演练来验证"的同构纪律——检查点的价值由故障恢复演练验证）。

## 边界

三条边界防止防线走形。

**微批是折中，有下限**：微批间隔压到秒级以下，调度开销吞掉收益且失去批的确定性优势——微批的合理区间是秒到分钟，向下不如直接流。

**流处理的状态有寿命**：窗口状态、去重状态会随 key 数量增长——状态 TTL 与过期策略是流任务的必配项，无 TTL 的长跑任务会被状态膨胀拖垮（RocksDB 后端的 compaction 恶化、内存后端的 OOM）。

**时间语义不可后补**：按处理时间建好的管道，事后想改事件时间要重放全量——**时间轴选择在管道设计期锁定**，这是批流选择里唯一"改不起"的决定。

## 验证

可复现的验证路径：

1. 时间语义验证：构造乱序事件流（已知的事件时间分布），按事件时间与处理时间各算一遍窗口统计——预期事件时间结果稳定、处理时间结果随延迟漂移，对照确认时间轴选对了；
2. 迟到验证：注入迟到事件（超过水位线），核对 allowLateness 策略的补算或丢弃行为与配置一致；
3. 恰好一次验证：制造故障（kill 任务），恢复后核对结果与无故障基线对账——重复计数或丢失即三层基建有缺口；
4. 批重跑验证：同一输入快照重跑两次，结果逐行一致；
5. 断言锚点：**流路径五项保障清单齐备且恢复演练通过；批路径重跑一致性验证通过**。

```text
时序断言 = 事件时间结果稳定，处理时间漂移可解释
恢复断言 = 故障恢复后与基线对账一致
重跑断言 = 批两次重跑逐行一致
```

批与流的选择在两条轴上各问一句，路径就从"团队偏好"变成"需求推导"——选批拿到确定性与便宜，选流拿到新鲜度并付出基建价格，账算清楚两条路都是好路。
