# 数据系统：在并发与故障中保存事实

数据系统的核心任务是在并发访问、进程崩溃、机器故障和版本变化下，仍能说明什么是真实状态。数据库产品只是实现；长期需要掌握的是数据模型、访问路径、事务、持久化、复制、恢复和运维边界。

## 从请求到持久事实

~~~mermaid
flowchart LR
    Q[查询或写入] --> P[解析与优化]
    P --> I[索引访问路径]
    I --> B[Buffer Pool / Page]
    B --> L[事务与日志]
    L --> S[持久存储]
    L --> R[复制与派生数据]
    S --> C[恢复与备份]
~~~

## 六个互相约束的问题

| 问题 | 关键机制 |
| --- | --- |
| 数据表达什么 | schema、约束、实体边界、版本与事实来源 |
| 如何找到数据 | B+Tree/LSM/哈希、统计信息、优化器、分区 |
| 并发看到什么 | 隔离级别、MVCC、锁、冲突与死锁 |
| 提交如何持久 | WAL/redo、undo、刷盘、原子提交 |
| 副本如何收敛 | 日志位点、延迟、一致性承诺、故障转移 |
| 如何恢复 | 备份、日志重放、RPO/RTO、恢复演练 |

## 先按工作负载选边界

选择数据库前描述：

- 读写比例、访问模式和查询形状；
- 并发连接、事务长度与热点；
- 数据量、增长、保留和删除；
- 一致性、可用性、延迟、RPO 与 RTO；
- 单机、跨进程、跨主机和多地域需求；
- 团队的备份、升级、观测和值班能力。

SQLite 把数据库作为应用直接访问的文件，部署和本地事务简单；客户端/服务端数据库通过网络协调更多并发和集中运维。这个区别通常比“谁更快”更重要。参见 [[工程知识/数据系统：在并发与故障中保存事实/事务与存储/SQLite与MySQL代表不同的并发与运维边界]]。

## 索引是写放大换读路径

索引按查询谓词、排序和关联方式设计。每个额外索引都会增加写入、存储、缓存和维护成本；联合索引的列顺序来自等值、范围、排序和选择性，而不是固定口诀。执行计划是优化器基于统计信息的估计，必须与实际行数和耗时对照。

## 事务是业务不变量的边界

隔离级别描述并发事务能观察到什么，不等同于“锁得更多就更安全”。MVCC 提供版本可见性，锁保护冲突操作；长事务会保留历史版本、延迟清理并扩大故障恢复成本。数据库事务只覆盖数据库内的原子边界，外部消息和 API 需要 outbox、幂等或补偿。

## 复制不是备份

复制提升读取扩展和故障恢复能力，也会快速复制误删与逻辑错误。备份需要独立保留、校验和恢复演练；高可用切换要定义数据丢失窗口、客户端重连、旧主隔离和只读副本陈旧度。

## 验证

1. 并发可见性：把同一组读写操作分别在四种隔离级别下执行，记录每种级别出现脏读、不可重复读与幻读的组合，预期结果与文档描述一致，偏差说明版本或参数不同。
2. 崩溃点恢复：在事务提交前、提交后返回前、日志刷盘前后分别终止进程，重启后核对数据是否持久、是否有部分写入残留。
3. 复制滞后：在主库持续写入的同时读取副本，记录滞后随写入速率的变化，确认延迟读与一致读分别观察到什么。
4. 恢复演练：对备份执行一次完整恢复，核实行数、业务不变量与账目。
5. 断言锚点：隔离级别行为逐项核对过，崩溃点恢复有记录，复制滞后进入监控，恢复路径演练过。

## 效果与代价

以数据模型、访问路径、事务、持久化、复制、恢复与运维边界为主线建立的判断，收益是更换数据库产品之后结论仍然成立、故障时能说明当前状态是什么，代价是需要把这些维度逐项写清楚，产品特性带来的便利不能被当作这些维度的替代。

## 可运行示例与案例回流：总纲的账

```text
同一笔转账在六个约束下的推演（通用形态）：

  原子性：A 扣 100 与 B 加 100 要么都发生要么都不发生 → 单机事务的回滚日志
  隔离性：B 在 A 转账中途读到"扣了 100 但还没加" → 隔离级别决定可见性
  持久性：提交成功后机器断电，钱不能丢 → WAL 先写日志再改数据页
  复制：主库提交了，从库还没收到 → 一致性窗口里读到旧值（复制不是备份）
  分区：用户表按地域分区后，跨区转账 = 跨分区事务 → 分布式事务的协调成本
  校验：对账任务每日核对"转出总额 = 转入总额"，差异即线索

  六个约束互相拉扯：隔离级别调高 → 并发下降；
  复制加同步节点 → 写延迟上升；分区越细 → 跨区事务越多
  总纲的作用：先按工作负载选边界（本篇），再用具体机制填细节（子篇）
```

案例回流：总纲失守的实录——团队把"数据库负责一切"当默认，单表 10 亿行后所有六个约束同时恶化（索引膨胀、主从延迟小时级、备份窗口超时）；按工作负载重新选边界（读写分离 + 冷热分表 + 归档）后各项指标回到可运维区间。复制当备份的实录——主库磁盘损坏切换从库，发现从库数据是三天前的（复制断了三天没人发现，监控只盯主库）；复制延迟与复制健康都要纳入监控，备份与复制是两套独立机制。各约束的展开账见本目录各子篇：隔离级别、主从复制、分区、事务、备份恢复；写路径质量责任的源头治理见 [[工程知识/数据系统：在并发与故障中保存事实/数据治理/数据治理把质量责任放到写路径上.md]]。

## 要解决的问题

并发访问、进程终止、机器故障与版本变化同时发生时，系统无法说明当前状态是什么，也不清楚哪些数据已经持久、哪些写入可能丢失。本篇回答：数据系统的核心任务是什么、数据模型与访问路径与事务与持久化与复制与恢复与运维各自回答什么问题、数据库产品在其中处在什么位置，以及一项判断依据怎样跨产品保持成立。
