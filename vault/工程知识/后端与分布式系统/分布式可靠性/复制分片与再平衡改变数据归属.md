# 复制分片与再平衡改变数据归属

它解决的是单节点容量、吞吐或可用性不足，但代价是同一条数据的归属和可见性变得动态。核心机制是用分片键决定写入归属、用副本协议决定可见性，再用版本化路由和迁移状态协调再平衡；验证需覆盖热点、迁移中读写、旧路由和跨片超时，确认无丢失、重复和旧节点写入。

复制把同一数据放在多个节点上以提高读取、可用性或容错；分片把不同数据放到不同节点以扩展容量和吞吐。两者都会改变请求路由、故障恢复、事务范围和运维复杂度。

## 选择维度

| 维度 | 必须定义 |
| --- | --- |
| 分片键 | 热点、倾斜、查询覆盖、租户隔离和不可变性 |
| 复制 | 同步/异步、读新鲜度、冲突和故障转移 |
| 路由 | 客户端/代理/目录、缓存、旧路由失效和重试 |
| 再平衡 | 数据迁移速率、双写/只读窗口、校验和回滚 |
| 跨片操作 | 是否允许、如何协调、超时和部分成功 |

一致 hash、range、目录映射或按租户分片各有边界；最重要的是分片键一旦改变，数据移动和请求路由必须版本化。热点复制可能解决读峰，却不能自动解决单 key 写冲突。

## 迁移状态机

一次再平衡至少要区分准备、复制、校验、切换和清理阶段。路由版本在切换前后都要可识别；旧 owner 可以完成正在进行的只读请求，但必须拒绝带旧版本的写入。迁移失败时保留源副本和校验点，避免“路由已切换、数据还未完整”的半状态。

最小实验：把一个热点分片从 A 迁到 B，在复制未完成、路由缓存未刷新和切换后分别杀掉 A/B；比较读到的版本、写入是否被旧 owner 接受、校验和以及回滚时间。没有这些证据时，“再平衡完成”只能算控制面状态。

## 验证

压测均匀和倾斜 key，注入副本延迟、主节点故障、路由缓存陈旧、迁移中读写、重复消息和跨片超时。检查数据完整性、重复/丢失、旧节点拒写、客户端重连和迁移后的容量分布。
