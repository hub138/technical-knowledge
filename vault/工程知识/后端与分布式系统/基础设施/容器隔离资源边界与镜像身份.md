# 容器隔离资源边界与镜像身份

容器共享宿主机内核，通过 namespace、cgroup、能力和文件系统层提供进程与资源边界；它不是虚拟机，也不是自动安全沙箱。镜像是运行输入的一部分，标签可变，摘要/签名才适合绑定产物身份。

## 需要显式限制

- CPU、内存、PID、文件描述符和临时盘；避免单容器拖垮节点。
- Linux capabilities、seccomp、用户身份、只读 rootfs、设备和 host namespace。
- 网络出站、DNS、代理、凭据和挂载；AI 工具执行尤其不能默认开放宿主机。
- 镜像基础层、依赖、构建 provenance、漏洞、许可证和运行用户。

资源 limit 解决超载隔离，不保证应用在 limit 内正确；health/readiness 只影响调度，不等于业务成功。镜像更新要使用不可变 digest，滚动部署要保留旧镜像和配置以便回滚。

## 最小隔离实验

在非生产节点运行一个尝试读取宿主路径、创建大量子进程、占满内存和访问受限网络的容器；分别开启只读根文件系统、非 root、drop capabilities、seccomp、PID/内存/临时盘上限，再记录被拒绝的系统调用、OOM、网络错误和容器退出原因。实验只能证明当前配置的边界，不能把容器当成对抗高权限攻击者的完整沙箱。

## 验证

检查容器逃逸、路径/符号链接、权限、网络访问、子进程、信号和优雅终止；压测 CPU throttling、内存 OOM、磁盘满、节点迁移和镜像冷启动。对 AI 服务额外测 GPU device、拓扑、驱动和模型权重挂载。
