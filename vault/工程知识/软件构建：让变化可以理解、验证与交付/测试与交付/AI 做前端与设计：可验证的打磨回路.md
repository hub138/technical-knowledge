# AI 做顶级 UI 设计：从创作到验证的完整回路

AI 做前端有两个 famous 的失败形态，分处流水线的两端。**创作端**：同样的提示词、同样的模型，别人做出来是一镜到底的惊艳页面，自己做出来永远是紫色渐变加圆角卡片——模型没变，变的是用法。**验证端**：页面"代码正确但体验错误"——按钮存在但黑底上看不见，卡片存在但内容被截断，这些不会在任何编译或 lint 里报红。两端的坑有一个共同的根源：**把判断的责任留给了模型自己**。这一篇把两端接成一条完整回路：创作端注入模型外部的约束（发散、意向、评审），验证端把判断变成可量化的断言（实测、门禁、归因）。设计能力不是模型的属性，是回路的属性。

## 要解决的问题：AI 生成的前端为什么一股 AI 味（先说结论）

| 阶段 | 做什么 | 防的是什么 |
|---|---|---|
| 创作 | 双钻石发散聚焦，多样性与意向从模型外部注入 | 委员会设计：安全、正确、毫无记忆点 |
| 评审 | 无历史包袱的子 agent 看截图打分，9 分以下循环改 | 执行 agent 自己夸自己 |
| 素材 | 图片生成、着色器、视频动画，超出纯代码的表现力 | "一眼看出是 AI 做的" |
| 删减 | 图形能传达的删文字，具体指令优于宏大指令 | AI 味的文案堆砌 |
| 验证 | 截图实测 + 量化门禁 + 抱怨归因 | "代码对但渲染错" |

## AI 味的根源：预测机制本身

理解第一件事是 AI 味从哪来。语言模型的工作方式是预测"最有可能出现的下一个 token"，而这个预测由人类评分反馈训练而成——模型学会的是**满足所有人偏好的、既稳定又安全的决策**。放在设计上，这就是"由委员会决定的设计"：蓝紫渐变、圆角容器、emoji 图标，不是模型偷懒，是它对"大多数人会喜欢什么"的最优猜测。

优秀的设计恰好与这个自然行为相反——它靠打破常规、令人意外来制造记忆点。所以整个方法论的第一性原理是：**想获得超越平庸的设计，就必须从模型外部注入模型自己不会产生的东西**。下面每个技巧都是这个原理的具体化。

## 创作：双钻石与外部注入

设计流程借用双钻石模型：先发散（找到真问题）、聚焦（定义核心问题）、再发散（穷举解法）、再聚焦（选定方案打磨）。对应到 AI 协作上，是三个具体动作：

**发散靠外部随机性**。直接让 AI"做四个设计方案"，得到的四版依然趋同——模型本质上做不了随机。多样性必须从外部给：要么用一个随机生成的字符串作为灵感源（让模型从字符串里读出配色、布局、字体方向的"暗示"），要么直接明确指定差异维度。后者在实践中更可靠——"四个方案，字体各不同、配色各不同、布局各不同，禁止左右分栏"比一个神秘字符串更可控。

**聚焦前先列意向**。动手写页面前，先让 AI 广泛地列设计意向——"为这个产品提出 15 种大胆的视觉语言，每种两句话，不求可行只求方向"——人从中挑出最有共鸣的一两个。意向是设计的灵魂，页面只是意向的执行；跳过意向直接写页面，得到的永远是模型的默认审美。

**执行提示词要具体到风格名词**。"大胆一点""惊艳一些"这类形容词没有信息量，模型听不懂。有效的写法包含具体的风格承诺："像素风格、每个板块有游戏感""等轴 45 度视角的 3D 城市，功能以建筑呈现""打破网格、贴边排布、不对称留白"。人的设计判断力在这里入场——风格名词是人选的，模型负责执行。

## 评审：无包袱的子 agent 循环

执行 agent 评审自己的设计有结构性缺陷：它带着全部历史上下文——它写的代码、它做的取舍、它对实现的偏好。这些包袱让它倾向于维护现状，质疑现状的动力不足。解法是把评审与执行分开：

```text
执行 agent：便宜快速的模型，负责改代码（机械化工作）
评审 agent：设计能力强的模型，零历史上下文，只看截图
输入：当前页面的全页截图 + 一句"这是给谁看的、交付物是什么"
要求：指出与顶级设计工作室呈现方式的最大差距；
      给出具体到可执行的修改意见（伪代码级，拒绝"更有设计感"这类空话）；
      按满分 10 分评分，标出任何"一眼 AI 生成"的俗套模式
门槛：9 分以上才算完成；不到 9 分，意见回传执行 agent，循环
```

这个循环的三个关键：**评审者必须零上下文**（不带代码、不带设计规范，只看画面）；**意见必须具体**（"把标题换成衬线体并在右侧加贴边卡片"能执行，"提升视觉层次"不能）；**分数是循环的终止条件**（没有分数，循环就没有终点）。评审用强模型是划算的——它上下文短、只做判断，成本远低于让它写代码。

## 素材：超出纯代码的表现力

纯代码的天花板是文字、SVG 和 CSS 效果。顶级设计几乎都依赖精致的视觉素材——一张高质量的背景图上随便排几个字就是苹果级的设计。三个补充手段按投入排序：

- **图片生成**：直接要求执行 agent 生成装饰性配图（透明底插画、抽象几何、氛围背景），放在容器衔接处或作为区块背景。一句"设计很简洁，可通过生成图片添加个性化元素，可结合着色器或 3D 效果"就能激活这个能力。
- **着色器**：点阵、波纹、流光这类 WebGL 效果，代码量小、视觉冲击大，适合鼠标跟随和区块过渡。
- **视频动画**：复杂角色动画用视频生成——生成绿幕背景的循环动画，程序抠色成透明底素材；需要交互时切成帧序列，随鼠标或滚动位置切换帧，就能做出一镜到底的滚动叙事。

素材的判断标准只有一条：它是否传达了品牌或情绪。为炫技而加的着色器和 AI 味的渐变是同一种错误。

## 删减：价值不来自添加

新模型的显著倾向是**到处写描述文案**——每个模块配一句解释、每个图标带一行标签。图形已经传达清楚的信息再配文字，是冗余；而它的另一个效果是让页面看起来"填得很满"，一眼生成感。

删减的判断标准：**图形能看懂的，文字删掉**；图标含义不明显的，文字反而要补上（或加悬停提示）。删减的指令同样要具体——"简化为以图像为中心的网格，去掉渐变、发光和不必要的容器元素"远比"追求极简风格"有效，后者模型执行不出来。

同理适用于文案本身：页面上的标题、按钮、引导语值得人亲手写或逐句审——模型写的文案抽象而正确，缺少具体的、有人味的表达。

## 验证：可量化的门禁

评审循环管"好不好看"，验证层管"有没有坏"。两者不可互相替代——评审 agent 同样看不见渲染结果，它看的截图里星标可能根本不可见，而它不知道那是 bug。

**实测三步**（每轮改动后固定执行）：无头浏览器全页截图 → CDP 读关键元素的几何与样式 → 与预期断言比对。本站实测抓过的真实案例：星标贴在黑底封面上整个不可见（代码写得好好的）、摘要两行截断切在半句话上、星标被 flex 换行挤到下一行单独站着——每一个都是代码审查放过的。

**门禁四类**（机器全量扫描）：对比度按 WCAG 断言（每页 × 每主题）、布局在 30 个视口宽度下无溢出无遮挡、链接全部指向真实目标、内容红线 grep 零命中。门禁的价值在回归防御——改 A 坏 B 的问题人眼复审不可能覆盖，机器扫完 22 个组合只要几分钟。

**归因四步**（用户抱怨的标准处理）：逐字分析（"太矮"= 高度由内容行数决定 → 内容被截断）→ 定位到 DOM 事实 → 修复 → 截图复测。每条抱怨背后都有一个可量化的 DOM 事实，找到它修复就是改一个属性。

门禁的边界也要诚实：它守"不坏"，"好"仍然来自评审循环里那个有品味的判断者。**门禁是回归网，不是质量本身。**

## 边界与教训

- **风格名词依赖人的输入**。"像素风""等轴 3D 城市"这些方向是人提供的——方法的本质是放大人的设计判断力，模型自身不会替你想到它们。积累自己的风格词库，比收集提示词模板更长期有效。
- **评审循环有收敛风险**。评审者若与执行者使用同一个模型家族，审美偏好相同，分数可能虚高。评审与执行用不同模型，分数才有区分度。
- **删减要有度**。含义不明的图标去掉文字会伤害可用性；删减的对象是"图形已传达的冗余文案"，不是所有文字。
- **门禁会误伤**：自动化检查偶尔因页面加载慢而误报超时，重跑即过。区分真失败和瞬时超时，别为偶发失败过度改样式。
- **门禁运行很慢**（对比度要起几十次无头浏览器）：轻量单项审计做日常检查，全量留给里程碑。

## 效果与代价

回路化打磨的收益是产出质量稳定可复现（评审子 agent 无包袱、素材库可积累），代价是回路轮次带来的时间成本与子 agent 的调用开销；直出模式的收益是快，代价是质量方差大——交付质量要求高的场合，回路成本是必要的，赶工场合的降级要显式决策。
