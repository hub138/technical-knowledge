# 依赖升级按风险分层，兼容性验证跟着层走

依赖不升级会腐烂（安全漏洞无人修、生态向前走时被甩下），盲目升级会断裂（breaking change 在构建期或运行期爆炸）。这两个方向的张力没有一刀切解，出路是**按风险分层**：把依赖按"变化如何伤到你"分型，每型配对应的升级节奏与验证深度。

分型的判据是依赖在你的系统里扮演的角色：

| 依赖类型 | 变化伤到你的方式 | 升级节奏 | 验证深度 |
| --- | --- | --- | --- |
| 直接 API 依赖（框架、库） | 签名/语义变化，构建期或测试期暴露 | 跟随 minor，major 缓一拍 | 全量测试 + 金样 |
| 运行时环境（语言、解释器） | 行为差异（GC、并发、默认值） | 锁定 minor，主动升 | 全量 + 性能基准对比 |
| 隐式依赖（传递依赖、平台库） | 你没 import 它却变了 | 锁文件钉死，定期统一升 | 冒烟 + 依赖扫描 |
| 协议/生态依赖（数据格式、API 规范） | 跨版本互操作断裂 | 跟规范节奏，双格式过渡 | 兼容性矩阵测试 |

隐式依赖最阴险：direct 依赖声明了 A@1.2，A 传递依赖 B@2.3，B 的行为你直接消费却从未声明。锁文件（lockfile）的存在就是把隐式依赖显式化——**没有锁文件的依赖树等于每次构建都在掷骰子**。供应链层面的锁定要求见 [[工程知识/软件构建：让变化可以理解、验证与交付/开发工具/依赖供应链需要锁定来源与构建输入]]。

## 升级的验证阶梯

升级不是二进制（升/不升），验证深度跟着依赖类型走：

1. **构建与静态检查**：编译通过、类型检查通过。这一层只能证明"签名没断"。
2. **测试套件**：单测加集成全绿。证明"测到的行为没变"——测不到的行为（时序、性能、边界输入）不在保证范围。
3. **行为对比**：金样测试（关键输入的输出快照对比）或双跑对比。覆盖测试测不到的语义漂移。
4. **性能基准对比**：同负载下升级前后的延迟/吞吐对比。运行时环境与重计算库必须做这层——行为全对但慢三倍的升级是失败的升级（基准的边界要求见 [[工程知识/性能工程：从用户等待到资源瓶颈/观测与诊断/基准测试必须先定义负载和测量误差]]，数据库侧的同类要求见 [[工程知识/数据系统：在并发与故障中保存事实/可靠性与运维/数据库基准必须描述负载与资源边界]]）。

语义化版本（semver）的承诺范围要认清：major 断兼容是明示的，minor/patch 不断兼容是**自觉**——依赖作者也是人，patch 里带行为变化的案例每个生态都有。所以"minor 升级不用跑全量验证"是错误假设，验证阶梯按依赖类型走，不按版本号走。

## 升级的时机策略

节奏上按类型分：安全补丁立即升（漏洞暴露窗口是攻击窗口）、minor 跟随但错峰（避免与自己的发布窗口叠加）、major 缓一拍（等社区把首批坑踩平，1-2 个 patch 版本后再进）。major 升级走绞杀者式的过渡：新代码路径用新 API，旧路径逐块迁移，两代并存期由开关控制（增量迁移的方法见 [[工程知识/软件构建：让变化可以理解、验证与交付/架构与代码/重构的安全边界由测试网和绞杀者模式共同划定]]）。

漏洞驱动的升级例外处理：紧急安全补丁可能只有 major 路径，此时验证阶梯压缩（构建 + 冒烟 + 灰度发布密切观察），风险从"升级断裂"换成"漏洞暴露"——显式记录这个交换，而不是假装压缩验证没有风险。

## 兼容性矩阵

多环境（开发/预发/线上、多语言客户端）共存时，兼容性是矩阵问题：依赖版本 × 消费方版本的每个组合都要么验证过要么声明不支持。矩阵爆炸的控制手段与 API 演进一致（见 [[工程知识/软件构建：让变化可以理解、验证与交付/架构与代码/API与Schema演进必须兼容新旧消费者]]）：支持窗口收窄（只支持 N 与 N-1）、数据格式双写过渡、旧版本显式 sunset 时间表。

## 边界

依赖图有边界成本：每个直接依赖都是长期负债（升级、安全、license、废弃监控），加依赖的决策应该像加雇员一样过评审。能标准库解决的不引三方，能自己 200 行写清楚的不引重框架——这不是 NIH（Not Invented Here），是负债意识：**依赖的价值要与它的维护成本对账**。

版本号之外还要盯废弃公告：作者声明 deprecated 的依赖（哪怕还能用）要进迁移计划，拖到生态断供再迁就是被动 major 升级。

## 验证

升级演练：对每个直接依赖，在隔离分支升到目标版本，走验证阶梯到该类型要求的深度，记录每层的实际发现（断在哪层、修了什么）。这份记录沉淀成该依赖的"升级档案"，下次升级的预期成本有据可查。

锁文件审计：定期检查锁文件与声明的偏差（npm ls / pip check 类工具）、传递依赖里的隐式变化。CI 里把"锁文件与声明不一致"设为失败，防止隐式漂移。

兼容矩阵回归：多客户端场景下，升级后在矩阵的每个支持格跑冒烟，任何一格断裂先决策（扩大支持 or 收窄窗口）再合并。
