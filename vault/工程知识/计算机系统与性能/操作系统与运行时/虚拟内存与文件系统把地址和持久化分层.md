# 虚拟内存与文件系统把地址和持久化分层

它解决的是应用地址、物理内存、文件缓存和持久化被混为一谈，导致错误的容量和崩溃恢复判断。核心机制是页表、page cache、脏页回写和 fsync 分别管理映射、缓存与耐久性；收益是隔离和吞吐，代价是缺页、回写尖峰和复杂恢复语义。用冷/热缓存、磁盘满、重启和断电模拟验证可见性与恢复。

进程看到的是虚拟地址空间，内核通过页表把它映射到物理页、文件映射或共享页。文件系统把文件名映射到 inode、块和缓存；`write` 返回只说明数据进入内核路径，不等于已经持久化到设备。

## 性能与正确性

- page fault、TLB miss、内存回收和 swap 会把 CPU 计算变成等待。
- page cache 让文件读写看似很快，但脏页回写和 `fsync` 会产生延迟尖刺。
- `mmap` 共享地址空间和文件页，减少拷贝但引入缺页、截断、并发和错误处理边界。
- `fsync`、目录同步、文件系统和设备缓存共同决定崩溃后哪些写入可见；应用不能只看返回码。

## 常见错误

把 RSS 当作“真实使用内存”、把 page cache 当作泄漏、把 `close` 当作持久化、把磁盘写入吞吐当作 fsync 延迟，都会导致错误容量和恢复判断。

## 最小映射实验

对同一文件分别使用 buffered I/O、`mmap` 和 direct/sync 写入，先测冷缓存再测热缓存，并在写入返回后模拟进程崩溃或重启。比较 page fault、dirty/writeback、fsync 延迟、可见数据和恢复结果，明确每种路径提供的是缓存性能还是持久性保证。

## 验证

观察 minor/major faults、RSS/匿名页/缓存页、dirty/writeback、IO wait、fd 和文件系统队列；分别测试冷/热缓存、随机/顺序、同步/异步写、磁盘满、重启和断电模拟。数据库和 RAG 索引的持久化、快照和恢复必须基于这些语义。
