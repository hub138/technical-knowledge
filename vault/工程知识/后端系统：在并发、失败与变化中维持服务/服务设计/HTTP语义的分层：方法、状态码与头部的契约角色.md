# HTTP语义的分层：方法、状态码与头部的契约角色

## 要解决的问题

HTTP 要解决的问题，是在两方之间建立一份**无需会话状态的请求契约**：客户端说"我对这个资源做这个操作"，服务端说"结果是这样"。它的机制本质是分层语义——方法（做什么）、状态码（结果如何）、头部（元信息与协商）各管一层，互相独立又组合成完整契约。这份契约让一个 1991 年设计的协议能承载今天的 API、流媒体、遥测与代理链，而不需要各方会话协商。词汇即接口（见 [[工程知识/软件构建：让变化可以理解、验证与交付/开发工具/词汇即接口：Linux与容器命令的词源与设计.md]]），HTTP 是这个词源命题最大的工程实现。

## 三层语义

**方法层**：动词定义操作语义。GET 安全且幂等（不改变资源状态、重复执行同效），PUT 幂等但不安全，POST 两者皆非。方法语义的完整谱系见 [[工程知识/后端系统：在并发、失败与变化中维持服务/任务与并发/幂等性的完整谱系：从操作语义到删除接口的天然陷阱.md]]。关键设计：方法语义是服务端承诺，客户端可据此决策——GET 可以无脑重试（安全保证），POST 重试要配幂等键（谱系文有展开）。

**状态码层**：数字定义结果类别。1xx 中间态、2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务端错。类别的存在让中间件（代理、负载均衡、重试逻辑）无需理解响应体就能做正确动作：4xx 不重试（重试结果不变）、503 可重试（配合 Retry-After 头）。状态码是给机器读的契约，不是给人看的标签——错误处理器按类别分支，不按具体码硬编码。

**头部层**：键值对承载元信息与协商。Content-Type 协商表达格式，Cache-Control 协商缓存行为，Authorization 携带凭证。头部的设计哲学：**每个头一个独立决策点**，中间件可以只读自己关心的头（代理读 Cache-Control，网关读 Authorization），互不干扰。头部可以随意扩展（注册新头即可），这是 HTTP 三层里演进最快的层。

三层合起来：**方法+状态码+头部 = 一次交互的完整语法**。任何一方（客户端、服务端、中间件）都只读自己需要的层，这就是无状态契约的可组合性来源。

## 背景与代价

思想背景：HTTP/1.0 的设计直接继承了 REST 思想的前身——Roy Fielding 2000 年的博士论文把"统一接口"列为 REST 的核心约束，方法是统一接口的动词部分。替代的是 RPC 风格的窄接口（每个操作一个端点、每个响应一个自定义格式）——窄接口表达力强但每个端点都要各方重新学习，统一接口让任何客户端用同一套动词与任何服务端交互。

最精巧的一笔是**状态码的类别语义**。5xx 与 4xx 的分界线是"谁的错"——这把责任显式写进协议，重试逻辑、告警路由、SLO 统计都靠这条线工作。代价要摆明：语义分层的代价是表达力的约束。POST 一个方法要承载"创建、执行、查询复杂条件"多种操作，语义靠请求体补足（REST 纯度之争由此而来）；状态码 60+ 个但常用不到 20 个，剩余的在实践中语义模糊（418 是愚人节玩笑成了真实规范）。

## 边界

- **语义分层不等于实现正确**。服务端返回 200 + 错误体是常见反模式（破坏重试逻辑与监控统计），正确做法是把结果类别写进状态码。
- **HTTP 语义与 HTTP/1.1、HTTP/2、HTTP/3 传输无关**。语义层（方法/状态码/头部）在三代协议里不变，变的是传输层（文本→二进制分帧→QUIC）。把"HTTP/2 多路复用"与"HTTP 语义"混为一谈是层次混淆。
- **代理链会改写语义**。转发代理改写 Host 头、CDN 注入 X-Forwarded-For、负载均衡把 502 翻译成 503——契约在中间件处会被"再解释"。请求落到哪里由服务发现与负载均衡决定（见 [[工程知识/后端系统：在并发、失败与变化中维持服务/服务设计/服务发现与负载均衡决定请求落到哪里.md]]），但"落到哪里之后发生什么"由语义层契约管。
- **REST 语义的完整谱系**： Richardson 成熟度模型（资源/动词/超媒体三级）是语义分层的应用深化，不是协议的一部分。超媒体（HATEOAS）是语义层的最高级，多数工程止步于第二级，这是务实选择不是缺陷。

## 验证

- **契约一致性验证**：对一个真实 API 抽样请求，预期：GET 不产生副作用（重复调用响应体一致）、4xx 不重试、5xx 配合 Retry-After 重试。对不上就停下查：网关或框架是否改写了状态码。
- **幂等承诺验证**：PUT 同一资源两次，预期资源状态与一次相同。PUT 的幂等承诺被服务端实现破坏（如 PUT 里嵌时间戳）是常见契约违例。
- **头部独立性验证**：给请求加自定义头 X-Debug: 1，预期响应多出调试信息且其他行为不变。头部被中间件剥掉时逐跳排查（代理、网关、CDN 各自的头部转发策略）。
