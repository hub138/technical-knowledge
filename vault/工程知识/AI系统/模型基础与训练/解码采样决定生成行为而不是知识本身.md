# 解码采样决定生成行为而不是知识本身

解码要解决的是模型给出概率分布后如何选择具体输出轨迹。它改变多样性、稳定性、长度和风险，不会增加模型未学到的事实；最小实验是固定 prompt 和模型，对同一问题集比较 greedy、低温和高温的格式通过率、引用支持率、重复率与成本。
模型每一步给出下一个 token 的概率分布，解码策略决定如何从分布中选取 token。温度、top-p、top-k、重复惩罚、停止条件和结构化约束会改变多样性、稳定性、长度和错误形式，但不能把缺失的事实变成可靠知识。

## 常见策略

| 策略 | 机制 | 适用倾向 | 风险 |
| --- | --- | --- | --- |
| greedy | 每步选最大概率 | 稳定格式、确定性任务 | 可能重复或陷入局部高概率 |
| temperature | 重塑 logits 分布 | 控制随机性 | 温度越高不等于创造力越有用 |
| top-p/top-k | 只在候选子集采样 | 开放式生成 | 截断会改变尾部概率质量 |
| beam search | 保留多条高分路径 | 某些序列生成任务 | 对开放式对话常变得保守、重复 |
| grammar/JSON schema | 将非法 token 路径屏蔽 | 结构化输出、工具参数 | 只保证语法，不保证业务语义 |

## 工程上最容易忽略的边界

- 同一 prompt 和模型，采样参数变化就可能产生不同工具调用和安全行为。
- `max_tokens`、stop sequence 和截断会改变完成条件；“返回 200”不代表任务完成。
- 结构化约束可能让模型在无法满足语义时输出形式正确的错误值。
- 流式输出中途断开、重试或重复提交时，调用方必须用幂等和状态机处理。

## 验证方法

在固定模型快照、prompt、工具 schema 和输入集下，分开测确定性、格式通过率、事实/引用、拒答、工具参数正确率、平均/长尾 token 和成本。生产任务按类型设定不同解码策略，不要用一个全局温度掩盖任务差异。
