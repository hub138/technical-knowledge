# 多模态模型把不同输入映射到共同推理接口

多模态模型解决的是文本、图像、音频或视频需要共同理解和行动，但不同模态的表示、时间尺度和噪声分布不同。工程上要验证跨模态对齐是否保留任务细节；最小实验是对原图、低分辨率图、遮挡图和文本描述比较结构化字段准确率与遗漏率。
多模态系统不是“把图片塞进 prompt”这么简单。图像、音频、视频和文本有不同采样率、空间结构、长度和信息密度，系统需要编码器、投影层、跨模态对齐和生成器，把它们转成模型可以共同处理的 token 或 latent 表示。

## 典型路径

```text
原始媒体 -> 解码/采样 -> 模态编码器 -> 投影/对齐
         -> 统一上下文 -> Transformer 推理 -> 文本/结构/动作输出
```

视觉 token 数受分辨率、切片策略和压缩影响；视频还要决定帧采样和时间粒度；音频需要区分语音识别、声学事件和说话人信息。输入预算、上传延迟和隐私风险因此成为上下文工程的一部分。

## 能力与边界

- 视觉语言模型可能擅长描述和视觉问答，但不天然保证像素级测量、空间几何或 OCR 的完整性。
- 音频转写错误会沿着后续摘要、检索和工具调用传播；需要保存原始片段和时间戳。
- 多模态输入的安全边界包括恶意图片文字、隐藏指令、文件元数据和跨模态提示注入。
- 生成图像/音频的安全、版权和真实性验证与文本生成不同，不能共用一个“通过率”。

## 验证

按模态、分辨率/时长、语言、噪声、遮挡、表格/代码和对抗样本分桶；同时记录 token/帧数、端到端延迟、转码失败、引用位置和人工核验结果。涉及动作或业务写入时，输出必须经过结构、授权和事实门禁。
