# 后训练对齐与微调改变行为边界

后训练解决的是预训练模型“会生成但不一定按任务格式、偏好、安全和工具契约行动”的问题。它改变行为分布，不是可靠写入新事实；最小对照应固定基础模型、prompt 和解码，只替换后训练版本，检查格式、工具参数、拒答和旧能力回归。
预训练形成通用表示和预测能力，后训练在较小但更有意图的数据上塑造“如何回答、何时拒绝、如何调用工具、输出什么格式”。监督微调、偏好优化和强化学习改变的是输入到输出的行为分布，不应被误解为可靠地写入一组新事实。

## 典型链路

1. **监督微调（SFT）**：用高质量示范把模型推向目标格式、任务和语气。
2. **偏好数据**：收集两个回答的相对偏好，训练奖励模型或直接优化偏好目标。
3. **RLHF/DPO 等优化**：提高偏好目标，但可能过拟合标注者、奖励模型或短期风格。
4. **安全与能力回归**：检查拒答边界、工具行为、事实、代码和长上下文是否互相牺牲。

## 为什么会发生能力退化

微调数据过窄会造成灾难性遗忘、格式过拟合和分布外性能下降；偏好目标可能奖励“听起来正确”而不是“证据充分”。模型更服从指令也可能更容易被恶意指令驱动。参数更新、LoRA、蒸馏和系统 prompt 的影响范围不同，必须分别记录。

## 什么时候不用微调

- 事实经常变化或必须引用：优先 RAG/权威工具。
- 只是临时格式或少量示例：优先 prompt 和结构化输出。
- 需要实时业务状态或副作用：使用受控 API/工具。
- 需要稳定风格、术语或重复行为，且有足够代表性数据：才评估微调。

## 评测门禁

微调前冻结基线、数据和环境；按任务切片比较质量、拒答、越权、引用、延迟、token、显存和成本。至少包含未见领域、冲突指令、长输入、工具错误和恢复样本。只有当目标切片收益超过回归和运维成本时，才进入灰度。
