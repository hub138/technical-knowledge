# Token、Embedding 与表示学习连接数据和模型

Token、Embedding 与表示学习分别回答“文本如何进入模型”“对象如何变成可检索的向量”“向量中的结构从何而来”。混淆它们会同时误判上下文容量、token 成本、索引内存和 RAG 召回质量。最小实验是对数字、否定、代码和多语言样本比较 token 长度、向量近邻、top-k 召回与索引内存。
模型看不到“文字”这个人类概念，只接收有限词表中的 token id，再把 id 映射为向量。Embedding 不是知识库，也不是相似度真理；它是把某种任务中的对象投到可计算空间的表示，质量取决于训练目标、数据分布、语言、粒度和使用方式。

## 三种容易混淆的表示

| 表示 | 产生位置 | 适合解决的问题 | 主要限制 |
| --- | --- | --- | --- |
| token id/词表 | tokenizer | 把原始序列编码成模型输入 | 切分会改变长度、成本和边界；不同模型不可直接混用 |
| token embedding | 模型输入层 | 为 Transformer 提供初始向量 | 是上下文无关的，不能单独表达句子意图 |
| 文本/图像 embedding | 专用编码器或模型池化 | 召回、聚类、去重、匹配 | 向量相近不等于事实正确、权限相同或答案可生成 |

## Tokenization 的工程后果

BPE、Unigram 等方法用子词在词表大小和序列长度之间折中。代码、表格、URL、中文、emoji 和混合语言可能产生完全不同的 token 密度；因此 token 数同时影响上下文预算、计费、prefill 延迟和批处理容量。换模型或 tokenizer 时，必须重新测长度分布，不要沿用旧成本估算。

## Embedding 空间如何被使用

给查询向量 `q` 和候选向量 `x`，常见相似度是余弦或内积。ANN 索引会牺牲一部分精确性换取延迟和容量；归一化、距离函数、维度、量化和索引参数必须与模型训练/接口契约一致。召回分数只能作为候选排序信号，最终证据仍需读取原文、检查权限和引用。

## 表示学习的边界

- 更大的向量维度不必然更好，可能增加索引内存和距离计算。
- 用生成模型的 hidden state 直接做检索，未必优于专门训练的 embedding 模型。
- 领域、语言、文档长度和查询形式发生变化时，向量空间会出现分布偏移。
- embedding 更新会改变邻居关系；新旧向量混用会让召回结果无法解释，必须有版本和重建策略。

## 验证清单

- 用真实查询标注相关性，比较 Recall@k、MRR/nDCG 和延迟，而不是只看向量分布。
- 按语言、文档类型、权限、长短查询和尾部样本分桶。
- 固定 tokenizer、embedding 模型、归一化、索引和过滤条件做 A/B。
- 记录模型版本、维度、距离函数、索引参数和重建时间；删除或撤权样本要验证不可见性。
