# 学习活动需要结果、轨迹与迁移证据

学习活动解决的是“看过内容”被误认为“能够独立使用”的问题。核心机制是把结果、操作轨迹、解释和新约束下的迁移分开记录；最小例子是先预测 RAG 召回结果，再运行一个小实验，最后改变权限或数据版本重新判断。
读完一页内容、生成一段摘要或答对一道原题，都不能单独证明学会。可用的学习活动必须让学习者解释机制、预测结果、完成操作，并在新情境中迁移；系统则保存这些行为和反馈，作为下一次复习与知识更新的证据。

## 一项活动的最小契约

```yaml
objective: "能解释重排为何改变 RAG 的有效召回"
prerequisites:
  - "理解倒排索引与向量召回的差异"
evidence:
  - "至少引用一个可核验来源"
activity: "先预测 top-k 变化，再比较两种排序结果"
feedback: "指出错误发生在召回、排序还是证据解释"
transfer: "把方法迁移到权限过滤或时效性场景"
source_revision: "2026-09-03"
```

契约先定义结果，再选择讲解、图谱、模拟、代码、测验或项目形式。形式可以变化，证据要求不能省略。

## 四层学习证据

| 层 | 观察什么 | 常见失败 |
| --- | --- | --- |
| 解释 | 能否用自己的话说明因果、前提和边界 | 复述术语但说不出为什么 |
| 预测 | 在看到结果前能否预测方向和代价 | 只会事后解释 |
| 操作 | 能否完成最小实验、代码或配置 | 懂概念却无法执行 |
| 迁移 | 能否在不同数据、约束或故障下复用 | 只会套原题模板 |

## 反馈要改变下一步

反馈不只是给分。先定位错误类型，再决定重建哪一层：缺基础就回到前置概念；机制混淆就用反例或关系图；操作失败就缩小实验并保存日志；迁移失败就增加相邻场景。重复做同一题不会自动消除错误。

## 评测与 Agent 评测共用边界

学习活动也应沿用 [[工程知识/AI系统/质量与运营/Agent评测必须覆盖轨迹而不只看最终答案]] 的原则：结果要能断言，轨迹要可回放，引用要能绑定来源，越权和副作用要被拒绝。模型可以生成解释和反馈，但不能自评为“已掌握”；掌握状态需要回答、实验或迁移任务的真实记录。

## 复习触发

复习优先级由三件事共同决定：上次活动的错误或不确定性、主题本身的变化速度、以及近期是否出现新的应用场景。主题更新时，只重做受影响的解释和迁移任务；稳定主题则按遗忘风险安排间隔复习。
