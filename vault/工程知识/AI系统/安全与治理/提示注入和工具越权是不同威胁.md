# 提示注入和工具越权是不同威胁

提示注入解决的是不可信文本试图改变模型指令，工具越权解决的是执行端授予了主体不应拥有的能力；前者是语义信任边界，后者是权限和资源边界。即使模型没有被注入，错误授权仍会造成越权；即使授权正确，注入也可能诱导模型浪费预算或泄露信息。
提示注入是输入影响模型指令解释的语义攻击；工具越权是系统实际允许不该允许的资源访问或副作用。前者可能诱导模型，后者决定诱导是否能造成损害。只在 system prompt 中写“不要泄露”无法替代身份、授权和执行隔离。

## 威胁路径

```text
不可信文本/网页/文件
        -> 模型上下文
        -> 错误的计划或工具参数
        -> 工具授权/数据边界缺失
        -> 读取、外泄或不可逆副作用
```

间接提示注入尤其危险：恶意指令藏在检索文档、邮件、网页、图片 OCR 或代码注释中。工具描述、返回内容和外部 Agent 消息也属于不可信输入，不能因为“来自工具”就提升权限。

## 防线分工

| 防线 | 负责 | 不能依赖 |
| --- | --- | --- |
| 身份与授权 | 每次调用确认主体、租户、资源和动作 | 模型自行判断权限 |
| 工具 schema/策略 | 限制参数、目标、范围和副作用 | prompt 中的格式要求 |
| 沙箱/网络隔离 | 限制文件、进程、网络和凭据 | “模型会遵守规则” |
| 审批与幂等 | 高风险动作确认、避免重复提交 | 单次输出看起来合理 |
| 日志与证据 | 保存输入、决策、实际命令和结果 | 模型声称“已完成” |

## 测试

构造直接/间接注入、工具投毒、跨租户查询、路径逃逸、旧凭据复用、参数替换、失败重试和审批后变更样本。断言必须是实际资源访问、响应内容和副作用，而不是模型说“我拒绝了”。
