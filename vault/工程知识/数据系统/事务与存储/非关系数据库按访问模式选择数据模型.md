# 非关系数据库按访问模式选择数据模型

键值、文档、宽列、图和时序系统不是“没有 schema 的数据库”，而是把 schema、查询、扩展和一致性边界放在不同位置。选型先从访问模式、数据关系、更新、事务、规模和运维能力出发，不能从产品标签推导设计。

同一份用户资料，如果主要按完整用户读取，文档模型可能减少连接；如果需要按多种关系、多租户条件和事务约束查询，反规范化的同步成本可能超过收益。模型选择是在访问路径和一致性成本之间做交换，不是把 SQL 换成另一种语法。

## 最小选型实验

用脱敏的真实查询分布建立 key-value、文档或关系模型的对照：固定数据量、热点比例、更新/读取比和故障预算，记录 p95/p99、跨分区请求、重复写、空间、备份恢复和开发复杂度。只有当主要访问路径和失败语义都通过，才把模型写入架构决策。

## 常见取舍

| 模型 | 擅长 | 代价 |
| --- | --- | --- |
| key-value | 已知 key 的低延迟读写 | 复杂查询和关系需要应用维护 |
| document | 聚合读取、局部嵌套变化 | 跨文档事务、重复数据和查询组合 |
| wide-column | 大规模分区读写、时间/键范围 | 查询必须围绕分区键建模 |
| graph | 多跳关系和邻接遍历 | 写入、分片、全局分析和运维复杂 |
| time-series | 时间窗口、压缩和保留策略 | 高基数标签、更新和跨域关联 |

反规范化是以写放大、同步和一致性换取读取路径；最终一致性、冲突解决、TTL、分区和重平衡必须写进业务语义。NoSQL 不能自动替代事务、约束、备份和审计。

## 验证

用真实 key/查询分布、热点、跨分区、重复/乱序、节点丢失、迁移和过期数据压测；比较一致性、p99、吞吐、空间、备份恢复和开发/值班成本。对 AI 记忆、检索缓存和向量元数据额外测租户/ACL 隔离。
