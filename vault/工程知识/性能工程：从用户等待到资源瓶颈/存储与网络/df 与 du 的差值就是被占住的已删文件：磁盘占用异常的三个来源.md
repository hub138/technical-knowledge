# df 与 du 的差值就是被占住的已删文件：磁盘占用异常的三个来源

> **要点**：磁盘"看起来满但找不到大文件"的排查按差值倒推——df 与 du 的差值是被进程握着的已删文件（`lsof | grep deleted` 定位，重启或截断释放）、超大目录是 du 的排序题（`du -x --max-depth=1 | sort -h` 逐层下钻）、特殊挂载与稀疏文件是 df 的虚胖（排除 `-x` 与 `--apparent-size` 两个参数纠偏）；三个来源各有一套标准动作，混合出现时按差值大小定优先级。

## 要解决的问题

磁盘告警触发后最常见的僵局：`df -h` 显示 95%，`du -sh /*` 加起来却只有一半——**空间去哪了**是每一次磁盘排障的第一问。三个来源覆盖了绝大多数情形：已删除仍被占用的文件（fd 未关闭）、du 看不见的挂载点遮挡、文件系统元数据与预留空间。本库"磁盘空间管理三原则"篇给了水位与配额的治理面；本篇给**排障动作面**：三个来源的判定与释放动作，按"差值优先"的顺序执行。

## 机制：三个来源的判定与释放

**来源一：已删除仍被占用（df/du 差值的主因）**。进程持有已删文件的 fd 时，空间不释放（inode 与数据块仍在，直到最后一个 fd 关闭）——典型现场：日志轮转后服务没重开日志文件（logrotate 的 copytruncate vs postrotate 之差）、临时文件写完就 unlink 继续用。**判定与定位**：`df -h` 与 `du -sh -x /` 的差值即嫌疑量级；`lsof +L1` 或 `lsof | grep deleted` 列出持有者（进程名、pid、大小排序）——**释放动作**按影响定：能重启的服务重启即释放；不能重启的截断文件（`: > /proc/<pid>/fd/<n>`，通过 proc 里的 fd 引用清空内容，空间立回）。**预防**：日志轮转配置里服务 reload 动作与轮转配对（本库"临时文件先写进命名约定"的命名与生命周期纪律同源：打开-写-关的完整生命周期有人管）。

**来源二：挂载点遮挡（du 看不见的目录）**。某目录被挂载后，原目录下的旧文件被"盖住"——du 扫不到、df 算得着。**判定**：`du -x -d1 /`（`-x` 不跨文件系统）与 df 的差值仍然对不上时，逐个挂载点检查：`findmnt` 列出全部挂载，对每个挂载点 `mount --bind / <临时目录>` 后进临时目录 du 原目录（看到被盖住的内容）——**释放动作**：确认无用的旧文件在卸载或 bind 后删除。高频现场：容器镜像层、临时挂载后的残留、快照挂载。

**来源三：文件系统的虚胖（元数据、预留、稀疏）**。ext4 的 root 预留（默认 5%，`tune2fs -l | grep -i reserved`）、海量小文件的 inode 耗尽（`df -i` 单独看，inode 满 + 块未满是"小文件洪水"的特征）、du 的 apparent size 与实际块占用的差异（稀疏文件、压缩）——**判定**：`df -i` 与 `df -h` 并排看（哪个先满用哪个判）；`du -h --apparent-size` 与不带参数的对比定稀疏与块开销——**释放动作**：小文件洪水走归档或清理（会话目录、断点文件是常见源）；预留比例按场景调（数据盘可降到 1%）。

**优先级纪律：按差值大小定动作顺序**。三个来源可能同时存在——先算 df/du 差值（来源一的量级），差值大先做来源一（动作快、无风险）；差值小再查来源二与三。**每次释放动作前后各记一次 df**，动作与效果的对应关系留痕（下一步动作的依据，也是事后复盘的账）。

## 看完能判断：三来源的现场特征

| 现场 | 第一动作 | 判据 |
| --- | --- | --- |
| 日志轮转后磁盘不降 | `lsof +L1` 找 deleted | 大文件在 deleted 列表 |
| 容器宿主机空间虚 | bind 挂载查遮挡 | `-x` 后差值仍在 |
| 创建文件报"空间不足"但 df 有余 | `df -i` 看 inode | IUse% 接近 100% |
| du 总量对不上 df | 查预留与稀疏 | tune2fs 与 apparent-size |

**预防的三条配置**：日志轮转与服务 reload 配对（消灭来源一的主要产生源）；临时目录独立挂载 + systemd-tmpfiles 清理（来源一与二的隔离，本库磁盘三原则篇的隔离原则）；inode 监控与块监控并排告警（来源三的先行指标）。

## 边界

三条边界防止防线走形。

**截断 proc fd 有前提**：`: > /proc/<pid>/fd/<n>` 对正在顺序写的日志文件安全（写偏移不变，后续写继续填充），对随机写或数据库文件有风险——**数据库类文件的释放走重启或引擎自带的空间回收**，不做 proc 截断。

**df 的统计与 du 的语义不同**：df 读文件系统的块位图（含预留、含 deleted-but-held），du 遍历目录树（跨挂载点、不含被遮内容）——两个数字本来就不同，**排查的起点是差值与 `-x` 参数后的修正值**，拿 du 总量去对 df 是语义错配。

**释放动作要过变更流程**：截断 fd、调预留比例、bind 排查都改变运行状态——高风险环境先备份判断依据（lsof 输出留档）再动手，动作与恢复路径写进变更单。

## 验证

可复现的验证路径：

1. 来源一复现：造一个 10GB 文件写入后 unlink 并保持进程持有，预期 df 满而 du 找不到，`lsof +L1` 检出，proc 截断后空间立回；
2. 来源二复现：目录写满后挂载 tmpfs 覆盖，预期 `-x` 的 du 看不到原内容，bind 后检出并可清理；
3. inode 复现：批量创建空文件到 IUse% 100%，预期"还有块却建不了文件"的特征与 df -i 判定一致；
4. 断言锚点：**df/du 差值进排障起手式、lsof +L1 与 df -i 在监控面板有对应告警、日志轮转 reload 配对在发布检查里**——三件齐备，磁盘异常从"找不到空间去哪了"变成三个来源的标准动作。

```text
差值断言 = df 与 du 的差是第一线索
释放断言 = deleted 文件有安全释放路径
并排断言 = df -h 与 df -i 并排看
```

磁盘占用的排障是一道减法题：df 管文件系统的账，du 管目录树的账，差值指认看不见的占用——三个来源的动作全部标准化后，"空间去哪了"从数小时的悬案变成十分钟的读表加一条命令。
