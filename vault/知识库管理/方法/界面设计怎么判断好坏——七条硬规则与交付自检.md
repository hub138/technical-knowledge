# 界面设计怎么判断好坏——七条硬规则与交付自检

判断界面好坏最怕"我觉得不好看"和"很现代"这两种话。读完这篇你能用可执行的规则替代感觉，冲突时有裁决顺序，交付前有自检清单。

规则提炼自 TDesign 的设计 Token 体系、ui-ux-pro-max 的 99 条 UX（User Experience，用户体验） 反模式库、frontend-design 的排版与动效章，以及本站自己的实测翻车记录。

## 四条规则打架时先按什么顺序裁决

四条规则打架时，按这个顺序裁：

1. **页面目的**——这个页面为什么存在、给谁看。给站长用的操作面板和给读者看的阅读页，密度和音量标准完全不同。
2. **用户的实际评价**——使用者的真实反馈压过一切理论。"信息量大"不构成对"看着乱"的反驳。
3. **通用法则**——下面那七条。
4. 法则内部打架时：**可读性 > 一致性 > 个性**。

## 哪七条硬规则不能违反

任何界面都成立，违反任何一条基本都是这里出过事故的：

1. **层级靠三个维度一起拉开**：字号、字重、颜色深浅。只动一个维度等于没层级。一屏内层级不超过四档：页面标题 / 区块标题 / 正文 / 辅助说明。
2. **不靠颜色单独承载信息**：红绿之外必须有图标或文字。色盲用户和深色模式都在替你检验这条。
3. **正文对比度 ≥ 4.5:1**，灰字压灰底是禁止项。muted 文字也要过线，不是"浅一点就行"。检测这件事有专门的工具：WebAIM 的对比度检测器输入前景与背景色值，直接给出对比度与 WCAG（Web Content Accessibility Guidelines，Web 无障碍内容指南） AA/AAA 判定，正文、大字号、图形三类阈值分开标注：

![WebAIM Contrast Checker 界面截图：输入前景色 0000FF 与背景色 EEEEEE，显示对比度 7.4:1，正文通过 WCAG AA 与 AAA 判定，大字号与图形组件两行分别给出通过状态](/static/figures/webaim-contrast-checker.png)

*图源：WebAIM 官网 Contrast Checker 页，https://webaim.org/resources/contrastchecker/（页面截图，2026-09-27）。*
4. **间距走阶梯**：2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64，区块级留白优先 16 / 24 / 32 / 48。出现 5px、13px、18px 这种阶梯外的值，基本是没设计，是凑。
5. **可点元素三件套**：hover 反馈 + `cursor: pointer` + 键盘 focus 可见。过渡 150–300ms，超过 500ms 让人不耐烦。
6. **不用 emoji 当 UI（User Interface，用户界面） 图标**：用 SVG，统一 viewBox 24，描边走 `currentColor`。emoji 在不同系统字体里基线（正常状态下的指标水平、用来对比异常）漂移、粗细不一，观感廉价。
7. **色值一律走 token**，不写死 hex。深浅主题靠 token 自适应；写死一处，另一处主题必翻车——本站深色模式下刺眼的白描边就是这么来的。

这套 token 体系长什么样，TDesign 官方色彩规范页一屏看全：主题色、功能色、中性色、扩展色四部分，每个功能色都标出白底与黑底上的对比度比值（正文 4.5:1 的硬规则在这里被做成了色卡上的第一行标注）：

![TDesign 官方色彩规范页：主题色 Tencent Blue 与功能色色卡，每列从 Brand-1 到 Brand-10 十档色阶并标注色值，色卡顶部标注 Contrast Ratio 白底对比度（Blue 7 成功色 3.4:1、Red 7 错误色 3.42:1 等），下方中性色灰阶与文字色在浅深两底上的 AAA 判定](/static/figures/tdesign-color-palette.png)

*图源：TDesign 官网设计规范「Color 色彩」页，https://tdesign.tencent.com/design/color（页面截图）。*

层级、间距、token 三条规则合在一个真实界面里是什么样，本站的知识全景页是现成实例：7 个知识层次 × 6 个知识类型的矩阵，每格标注篇数与字数，色阶从浅到深表示密度档位（1-2、3-7、8-15、16+ 四档图例明示），空格用红色虚线框标出——密度一眼可读、层级不靠颜色单独承载（数字同时在），是「把好坏拆成可数状态」的方法在自己身上的应用：

![站点知识全景矩阵页：行是 7 个知识层次（硬件与机器、操作系统与运行时、网络与通信、数据与存储、分布式与协调、应用与架构，每行标注子项），列是 6 个知识类型（机制原理 164、工程实践 46、观测诊断 39、修复与规避 50、故障模式 150、词汇与词源 4），每格填篇数与字数、按密度着色，右上角合计 453，色阶图例标 1-2/3-7/8-15/16+ 四档，词汇与词源列三个红框空格标缺口，「漏掉的方面」折叠行显示空格 3、单薄 4](/static/figures/panorama-overview.png)

## 哪两条经验是反直觉的

这两条不是抄来的，是本站改版改出来的：

- **引导元素要颜色和位置一起设计**。颜色对但埋没 = 没用；位置对但刺眼 = 反感。音量降到所在容器级别：导航项级的引导就用导航项的样式，不要升级成大卡片。本站的引导位迭代过四版：大黄卡（有效但过重）→ 安静小行（没有引导力）→ 实底框（和"当前位置"混淆）→ 暖橙导航项（可用）。
- **"当前位置"和"推荐"是两套语义**，必须视觉可区分。当前位置由路由决定，回答"你在哪"；推荐由人工钉选，回答"先看这个"。两者叠加时观感要自洽。当前位置的样式是神圣的，挪用一次去做别的，导航的定位功能就废了。

## 交付前按什么顺序自检

改完界面，按顺序过；"觉得不对但说不清"时也按这个顺序排查：

1. **层级与可读性**：四档以内；对比度两个主题都验过；正文行宽 ≤ 760px；没有 11px 以下的正文。
2. **布局与密度**：间距全在阶梯上；页面底 / 内容区底 / 卡片底三级拉开，卡片能"浮起一档"；删掉的区块有补位；375 / 768 / 1024 / 1440 四个宽度各截一次图，无横向滚动。
3. **状态与交互**：hover / focus / 当前 / 禁用四态齐全；加载超过 300ms 有骨架屏；空态有说明有动作；错误有下一步。
4. **文案**：没有讲"过程、口径、统计方法"的说明段；没有英文装饰小字；通读一遍没有幼稚表达。
5. **实证**：截图看（深浅两主题各一张），不是看代码；关键路径真点一遍；换个宽度换份数据再验一次。

## 实测翻车的现象与真因怎么对照

| 现象 | 真因 |
| --- | --- |
| 深色模式刺眼 | 写死色值，没走 token |
| 导航不知道自己在哪 | 当前态样式被挪去做别的事 |
| 页面看着空 | 元素删了没补位，只删不排 |
| 同一件事两个数字 | 两个页面统计口径不同却都写出来 |
| 行尾按钮被裁掉半截 | meta 行 overflow:hidden，前面的元素 flex:none 不收缩 |
| 图标看着廉价 | 用了 emoji 或字符，没有统一 SVG |

## 它和本库其他方法是什么关系

- 文章怎么写归 [[知识库管理/方法/一篇知识怎么写]]；界面怎么改归这一篇。两者冲突时，页面目的先决定"放不放"，写作规范决定"怎么写"。
- 质量判据的通用思路（信号可核对、不靠感觉）与 [[知识库管理/方法/知识完善度怎么判断——四象限与九个信号]] 同源：把"好不好"拆成可数的状态，而不是争论品味。
