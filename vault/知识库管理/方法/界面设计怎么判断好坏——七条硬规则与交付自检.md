# 界面设计怎么判断好坏——七条硬规则与交付自检

判断一个界面好不好，最怕两种话：一种是"我觉得不好看"却说不出哪里不好，一种是"信息量大、很现代"这种拿风格替判断。这一篇把判断拆成可执行的规则：冲突时有裁决顺序，落地时有硬规则，交付前有自检清单。规则提炼自 TDesign 的设计 Token 体系、ui-ux-pro-max 的 99 条 UX 反模式库、frontend-design 的排版与动效章，以及本站自己的实测翻车记录。

## 先定裁决顺序，再谈法则

四条规则打架时，按这个顺序裁：

1. **页面目的**——这个页面为什么存在、给谁看。给站长用的操作面板和给读者看的阅读页，密度和音量标准完全不同。
2. **用户的实际评价**——使用者的真实反馈压过一切理论。"信息量大"不构成对"看着乱"的反驳。
3. **通用法则**——下面那七条。
4. 法则内部打架时：**可读性 > 一致性 > 个性**。

## 七条硬规则

任何界面都成立，违反任何一条基本都是这里出过事故的：

1. **层级靠三个维度一起拉开**：字号、字重、颜色深浅。只动一个维度等于没层级。一屏内层级不超过四档：页面标题 / 区块标题 / 正文 / 辅助说明。
2. **不靠颜色单独承载信息**：红绿之外必须有图标或文字。色盲用户和深色模式都在替你检验这条。
3. **正文对比度 ≥ 4.5:1**，灰字压灰底是禁止项。muted 文字也要过线，不是"浅一点就行"。
4. **间距走阶梯**：2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64，区块级留白优先 16 / 24 / 32 / 48。出现 5px、13px、18px 这种阶梯外的值，基本是没设计，是凑。
5. **可点元素三件套**：hover 反馈 + `cursor: pointer` + 键盘 focus 可见。过渡 150–300ms，超过 500ms 让人不耐烦。
6. **不用 emoji 当 UI 图标**：用 SVG，统一 viewBox 24，描边走 `currentColor`。emoji 在不同系统字体里基线漂移、粗细不一，观感廉价。
7. **色值一律走 token**，不写死 hex。深浅主题靠 token 自适应；写死一处，另一处主题必翻车——本站深色模式下刺眼的白描边就是这么来的。

## 两条反直觉的经验

这两条不是抄来的，是本站改版改出来的：

- **引导元素要颜色和位置一起设计**。颜色对但埋没 = 没用；位置对但刺眼 = 反感。音量降到所在容器级别：导航项级的引导就用导航项的样式，不要升级成大卡片。本站的引导位迭代过四版：大黄卡（有效但过重）→ 安静小行（没有引导力）→ 实底框（和"当前位置"混淆）→ 暖橙导航项（可用）。
- **"当前位置"和"推荐"是两套语义**，必须视觉可区分。当前位置由路由决定，回答"你在哪"；推荐由人工钉选，回答"先看这个"。两者叠加时观感要自洽。当前位置的样式是神圣的，挪用一次去做别的，导航的定位功能就废了。

## 交付前自检五遍

改完界面，按顺序过；"觉得不对但说不清"时也按这个顺序排查：

1. **层级与可读性**：四档以内；对比度两个主题都验过；正文行宽 ≤ 760px；没有 11px 以下的正文。
2. **布局与密度**：间距全在阶梯上；页面底 / 内容区底 / 卡片底三级拉开，卡片能"浮起一档"；删掉的区块有补位；375 / 768 / 1024 / 1440 四个宽度各截一次图，无横向滚动。
3. **状态与交互**：hover / focus / 当前 / 禁用四态齐全；加载超过 300ms 有骨架屏；空态有说明有动作；错误有下一步。
4. **文案**：没有讲"过程、口径、统计方法"的说明段；没有英文装饰小字；通读一遍没有幼稚表达。
5. **实证**：截图看（深浅两主题各一张），不是看代码；关键路径真点一遍；换个宽度换份数据再验一次。

## 实测翻车对照表

| 现象 | 真因 |
| --- | --- |
| 深色模式刺眼 | 写死色值，没走 token |
| 导航不知道自己在哪 | 当前态样式被挪去做别的事 |
| 页面看着空 | 元素删了没补位，只删不排 |
| 同一件事两个数字 | 两个页面统计口径不同却都写出来 |
| 行尾按钮被裁掉半截 | meta 行 overflow:hidden，前面的元素 flex:none 不收缩 |
| 图标看着廉价 | 用了 emoji 或字符，没有统一 SVG |
