# 知识质量标准

这页回答“当前哪些内容可以直接用、哪些内容需要核验”。它不是知识正文；每月按 [[知识库管理/维护/知识演化机制]] 复查并更新。

## 分层结果

| 层级 | 判定 | 当前范围 | 使用方式 |
| --- | --- | --- | --- |
| Core | 有明确主题、机制、边界、来源和验证路径 | `工程知识` 中的 active 主题页 | 可作为日常决策入口；版本相关结论仍按复查日核验 |
| Curated | 有复用价值，但仍依赖版本或环境 | 当前主知识区为 0；以后只有通过主题合并门禁的内容才进入主区 | 不作为长期状态，必须提升或降级 |
| Needs review | 含旧版本、供应商 preview、硬件参数或单一来源 | 更新雷达标注的 preview 条目、限时待核验内容 | 只能作为候选，不直接复制到生产 |
| Source only | 不可替代的项目证据、会议案例、论文和产品材料 | `知识库管理/来源`、`Clippings` | 回溯证据；先提炼再引用；可由官方重新获取的课程副本不保留 |

## 页面评分

新页面发布前按五项各 0-2 分自评：

1. **问题价值**：是否解决会重复出现的设计、排障或决策问题？
2. **机制清楚**：是否解释因果、前置条件和失败边界，而非只给结论？
3. **证据可靠**：是否有官方文档、论文、实验、日志或可复现代码？
4. **可执行**：是否有验证命令、指标、样本、回滚或下一步？
5. **可维护**：是否有来源、版本、change_rate、review_after 和相关链接？

总分 8 分以上可进入 Core/Curated；5-7 分保留为 Needs review；低于 5 分移入来源层或删除。涉及权限、安全、价格、模型/API 和协议的页面，即使分数高也必须保留复查日期。

分数只能做发布门禁，不能替代人工判断。页面还必须通过三个反问：读者能否在 30 秒内知道它解决什么问题；能否沿着机制解释收益和代价；能否用例子、实验或来源反驳其中的关键主张。任何一项为否，都应继续重写而不是靠补标签提分。

## 演进型知识的额外门禁

- 不以“发布日期较新”代替技术价值，必须指出它解决的上一代瓶颈。
- 不删除仍是前置心智模型的旧原理；删除已经被新机制覆盖、又不能帮助判断的旧操作细节。
- 区分论文原型、厂商预览、可用产品和已验证实践，不能用同一种确定语气描述。
- 新增概念必须连接到稳定原理、替代方案、工程代价和验证路径，而不是成为孤立名词页。
- 复查时同时检查“事实有没有变”和“这个页面是否仍值得单独存在”；后者为否时合并后删除。

## 每月检查清单

- [ ] 主区没有新建按课程、日期、模型名称或项目名称命名的长期页面。
- [ ] review_after 到期页已核对来源、版本、API、价格、许可证和实验结果。
- [ ] 内部链接没有指向已删除或旧分类路径；孤儿页有明确去处。
- [ ] 论文/项目条目都记录了问题、方法、证据、边界和是否影响现有 Wiki。
- [ ] 新增内容没有密钥、密码、内部地址、个人信息或不可公开截图。
- [ ] Markdown 能被 Obsidian 打开，且实时知识站可重新扫描、渲染并生成内部链接图谱。
