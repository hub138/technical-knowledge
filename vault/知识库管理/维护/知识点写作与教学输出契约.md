# 知识点写作与教学输出契约

知识库的最小单位不是“资料摘要”，而是一个能够帮助人做出判断、完成操作并迁移到新场景的知识对象。每个对象都要把概念、因果、价值、证据和行动连在一起；展示形式根据学习目标变化，不能把所有内容压成同一种长文。

## 一页知识必须回答什么

```yaml
problem: "它解决了什么真实问题？不解决会付出什么代价？"
essence: "用一句话说明本质，去掉产品名和流行术语后仍成立"
mechanism: "输入、状态、转换、输出和反馈如何形成因果链"
benefit: "它改善哪个指标或决策？收益来自哪一个机制？"
example: "一个最小、可复现、能看到结果的例子"
boundary: "前提、失败模式、反例和不应使用的场景"
verification: "来源、实验、日志或测试如何证明主张"
relations: "前置概念、替代方案、下游影响和相邻主题"
freshness: "版本、发布日期、变化速度和下一次复核日期"
```

“是什么”只能作为入口，不能代替“为什么、何时、怎样验证”。如果一个页面删掉产品名后就只剩口号，它还没有抽象出可复用的机制。

## 核心拆解是内容门禁，不是排版模板

每个长期知识对象都必须能从正文中找到六个答案：它在解决什么问题，核心机制是什么，如何落地，带来什么收益和代价，在哪些边界失效，以及怎样用来源或实验验证。答案可以由小标题、表格、图旁说明或连续段落组成；不要求所有页面使用同一套标题。

发布前运行 `python3 scripts/audit-knowledge-quality.py`。检查器只扫描 `工程知识` 中的概念、指南、手册、原理、决策和架构页，导航型 overview/map 页不冒充知识正文；它会检查元数据、来源、因果六维和至少一个可解析的 Obsidian 关联。检查通过只是最低门槛，仍需人工判断内容是否具体、可反驳、值得长期保留。

## 先判断知识对象，再选择结构

知识页不应共享一套僵硬模板。先判断读者正在理解哪一种对象，再保留足以形成正确心智模型的结构：

| 知识对象 | 主线 | 必须补足 | 常见失败写法 |
| --- | --- | --- | --- |
| 原理与概念 | 问题 → 本质 → 因果 | 反例、前提、与相邻概念的区别 | 用同义词重复定义，只说“有什么” |
| 算法与协议 | 输入 → 步骤 → 不变量 → 输出 | 复杂度、故障分支、最小样例 | 只抄流程，不解释为什么正确 |
| 系统与架构 | 约束 → 组件 → 数据/控制流 → 状态 | 一致性边界、容量、降级与恢复 | 只有组件框图，没有请求和失败路径 |
| 工具与产品 | 问题 → 能力 → 实现机制 → 适用边界 | 版本、依赖、替代方案、真实体验 | 把 README 功能列表当作知识 |
| 选型与决策 | 目标 → 约束 → 备选 → 取舍 | 决策矩阵、退出条件、复核触发器 | 脱离负载和组织条件做排行榜 |
| 演进与前沿 | 旧瓶颈 → 新机制 → 收益 → 新代价 | 稳定内核、已过时部分、一手证据、复查日期 | 按年份堆名词，或把“新”误写成“好” |
| 排障与复盘 | 现象 → 假设 → 观测 → 根因 → 修复 | 最小复现、反证、回归和影响范围 | 把最终命令记录成流水账 |

这张表定义的是叙事主线，不是必须逐项出现的标题。一个页面只保留对当前知识对象有解释力的部分；缺少关键因果或证据时，不用更多小标题掩盖空洞。

## 同一页面提供三层阅读深度

一篇成熟知识页应该允许读者按时间预算进入，而不是要求从头读到尾：

1. **30 秒定位**：标题和开头直接说明问题、本质与何时值得继续读；关键图能独立表达一条关系。
2. **5 分钟理解**：解释机制、收益来源、主要取舍，并给出一个能观察到结果的例子。
3. **深入使用**：提供异常路径、验证方法、决策条件、一手来源和通往相邻主题的链接。

摘要不能与正文割裂。第一层给出可检验的结论，第二层展开因果，第三层让读者能够操作、反驳或迁移；后面的内容是在证明前面的结论，而不是另起一个资料堆。

## 时效内容必须写出演进因果

“最新”不是保留更多产品名，而是能解释技术为何从上一代走到当前形态。时间敏感主题至少区分四层：

- **稳定内核**：跨版本仍成立的目标、约束、数学或系统原理。例如 RAG 的稳定内核是用外部证据改变生成上下文，不是某个向量数据库接口。
- **被暴露的瓶颈**：旧方案在哪种规模、数据、权限、延迟或质量约束下失效。没有瓶颈，就无法解释演进方向。
- **当前机制**：新方案改变了哪一段信息流、控制流或反馈回路，因此改善什么指标，又引入什么成本。
- **待验证方向**：尚未稳定的论文结果、预览能力和厂商声明必须单列，标明来源日期、复现状态和下一次复核时间。

所以“传统 RAG → 混合召回 → 重排 → 查询规划 → Agentic RAG”不能只画成时间线。要逐步回答：上一阶段漏掉了什么信息，新增机制在哪里介入，质量、延迟、成本和可观测性怎样重新权衡。旧概念若仍是理解新机制的前置条件就保留，否则只在演进说明中出现，不继续占一个独立核心页面。

## 从目标选择输出形式

| 学习目标 | 首选输出 | 需要观察的证据 | 适合的技术图 |
| --- | --- | --- | --- |
| 建立心智模型 | 分层解释、概念对比、反例 | 学习者能说明因果和前提 | Architecture、Data Flow |
| 理解过程和状态 | 可点击流程、状态机、序列 | 能预测下一步与异常分支 | Workflow、Sequence、Lifecycle |
| 形成操作能力 | 最小实验、代码任务、配置实验 | 命令、产物、退出码和结果 | Data Flow、Sequence |
| 做技术选型 | 决策表、象限、约束对比 | 能说明取舍而非背排名 | Quadrant、Architecture |
| 检查可靠性 | 轨迹回放、证据审查、故障注入 | 声明能绑定到真实证据 | Workflow、Lifecycle |
| 迁移到新问题 | 项目任务、PBL、变体题 | 在不同数据和约束下仍成立 | Architecture、Data Flow |
| 保持长期记忆 | 检索题、间隔复习、错因卡 | 间隔后独立回忆并修正 | 简图 + 结果记录 |

图不是装饰。每条线都应该有语义：调用、依赖、数据流、状态转移或证据引用。没有语义的连线只会制造“看起来有关”的错觉。

## 一条完整的学习路径

```mermaid
flowchart LR
    O[定位问题与目标] --> E[解释本质与机制]
    E --> P[先预测结果]
    P --> L[完成最小操作]
    L --> V[检查来源与运行证据]
    V --> T[迁移到新约束]
    T --> R[记录错因并安排复习]
    R --> E
```

先预测再揭示答案，可以区分真正理解和事后复述；先做小实验再谈生产方案，可以把概念错误与环境错误分开；迁移任务必须改变数据、负载、权限或故障条件中的至少一项，否则只是原题重放。

## 三种证据不能混写

| 证据层 | 说明 | 不能推出什么 |
| --- | --- | --- |
| 来源证据 | 官方文档、论文、源码、发布记录和引用位置 | 不能推出本地环境一定能运行 |
| 执行证据 | 命令、版本、退出码、日志、产物和复现结果 | 不能推出所有场景都适用 |
| 学习证据 | 解释、预测、操作和迁移中的真实表现 | 不能替代产品事实或安全审计 |

模型可以提出解释、生成练习和归纳错因，但不能把自己的文字当作来源或执行证据。页面只有在三层证据的边界清楚时，才适合进入核心导航。

## 从四个项目吸收的做法

### Archify：让关系可验证

用类型化的图描述承载意图，用确定性校验检查结构、布局、链接和交付；失败时保留上一次通过的结果。知识库因此应把“图的数据”和“图的渲染”分开，图节点回到具体主题页或证据文件，坏图不能覆盖可信图。

### OpenMAIC：让内容匹配学习场景

同一主题可以生成讲解、测验、互动模拟、代码任务、项目制任务或复习路径。先确定要改变的学习行为，再选择页面类型；不要为了展示功能给每个主题强行添加动画或测验。

### DeepTutor：让能力、记忆和来源分层

对话、深度研究、可视化、知识库、记忆和笔记是不同能力，应该按问题路由；短期会话、工作区状态和长期主题也有不同生命周期。外部索引可以服务检索，但主知识仍要能回到可编辑、可审阅的来源。

### Matt Skills：让研究可交付、让反馈进入下一轮

研究先追到一手来源，再输出带引用的 Markdown；短期事实不冒充永久决策；优先复用已有模板和组件；反馈要改变下一步任务，而不是只给一个分数。研究文件如果没有被主题、决策或实验再次使用，就应归档或删除。

## 发布前的硬检查

- 页面标题描述的是概念、机制或决策问题，不是课程名、日期或一次性项目流水账。
- 开头能说清问题价值；中段能解释机制和收益；后段包含边界、验证、示例和相关链接。
- 至少一个关键主张有可访问的来源或本地实验；版本敏感内容有 `review_after`。
- 输出形式与目标匹配：需要判断就给对比，需要操作就给实验，需要迁移就给变体任务。
- 交互、图片和图谱有真实信息，不用装饰性连线掩盖缺证据；移动端也能阅读。
- 没有密钥、密码、私有地址、未经授权的截图或不可公开的个人信息。

低于这些标准的内容进入来源或候选层，不为了“看起来完整”留在核心区。删除一个无法复用的摘要，通常比让它污染搜索、图谱和后续模型上下文更有价值。
