# 知识库范围与结构

## 知识主区

\`工程知识\` 只按知识对象分成五个领域，不按课程、工作/大学、时间、作者或资料格式分类。

| 领域 | 下层主题 |
| --- | --- |
| AI 系统 | 模型基础与训练、模型与上下文、Agent 与工作流、知识与检索、推理服务与平台、数据与 MLOps、安全与治理、质量与运营、生态与选型 |
| 后端与分布式系统 | 服务设计、任务与并发、分布式可靠性、基础设施 |
| 数据系统 | 数据建模与 SQL、事务与存储、查询与索引、数据管道与流处理、数据治理、可靠性与运维 |
| 计算机系统与性能 | 操作系统与运行时、处理器与内存、存储与网络、观测与诊断 |
| 软件构建与质量 | 算法与数据结构、架构与代码、语言与运行时、测试与交付、开发工具 |

每个领域只有一个总入口。具体页面围绕一个可复用判断组织：解释机制与因果，指出适用和失效边界，给出验证方法，并连接上下游主题。

## 管理区

| 位置 | 内容 |
| --- | --- |
| \`更新候选\` | 尚未完成来源核验、价值判断或主题归并的外部变化 |
| \`来源\` | 论文、项目、官方资料和不可替代的实践证据 |
| \`维护\` | 演化机制、质量标准、学习方法和变更记录 |
| \`附件\` | 被当前页面引用的图片及附件 |

来源不是第二份知识正文。有效结论进入对应主题页，来源层只保留回溯所需的原始证据、研究记录和模板。

## Clippings

\`Clippings\` 保持独立且不改写。剪藏中的结论只有通过来源核验和主题归并后，才进入工程知识；原始剪藏继续作为来源保留。

## 新内容如何归位

- 能解释稳定机制或工程决策：合并进相应主题页。
- 会随版本快速变化且已影响选择：进入该领域的技术动态页。
- 有证据价值但尚不能形成通用结论：保留在来源。
- 尚未核验：进入更新候选，并在一周内处理。
- 重复、失效、无证据且可以重新获得：删除。
