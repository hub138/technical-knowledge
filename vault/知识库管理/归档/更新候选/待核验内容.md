# 待核验内容

这里记录**尚未完成来源核验、价值判断或主题归并**的内容。**候选区不是长期存储区**。

**每日外部更新可通过 Obsidian 的 Daily Notes 自动创建**到 `知识库管理/更新候选/每日更新`，模板使用 [[知识库管理/归档/更新候选/每日更新模板.md]]。

每条新内容尽量补充四项：

- **结论**：这条内容解决什么问题？
- **场景**：什么时候适用，什么时候不适用？
- **证据**：来源、代码、实验或故障现象是什么？
- **下一步**：移动到哪个主题，还是归档/删除？

**建议每周清理一次：有复用价值的内容进入对应主题目录，项目经验也归入实际主题；一周内仍无法说明价值、来源或下一步的候选直接删除，不转移到永久“待整理”区。明确无价值的重复、空占位和生成物立即删除**。

## 2026-10-08 AI技术动态周报

- vLLM v0.31.0 把请求级多模态处理参数（`mm_processor_kwargs`、`media_io_kwargs`）改成需服务端显式开 `--trust-request-mm-kwargs` 才接受；多模态服务的启动参数要同步打开，否则这类请求直接报错而不是降级（来源：<https://github.com/vllm-project/vllm/releases/tag/v0.31.0>）。
- vLLM v0.31.0 改了前缀缓存的块哈希输入，LoRA 路径计入哈希、附加键按来源打标，LoRA 名与 `cache_salt` 不再互相覆盖；升级后重测前缀缓存命中率，旧的命中率不再可比，混用 LoRA 与 `cache_salt` 的部署要验隔离（来源同上）。
- vLLM v0.31.0 把等待队列换成「已持有 KV 块的请求优先」的 KV 持有队列，取代原来的 `skipped_waiting`；在满负载下重测排队顺序与抢占行为，不是只看吞吐（来源同上）。
- vLLM v0.31.0 新增 `vllm preload` 常驻权重守护进程，把 Fast Start 从单次加载提速扩成跨重启保留量化后权重；采用前先算常驻显存占用，再看多模型轮换是否真的受益（来源同上）。
- vLLM v0.31.0 起 Model Runner V1 与流水线并行大于 1、异步调度、结构化输出的组合在启动时被直接拒绝；还在用 MRV1 的部署按这组条件自查，迁 V2 验的是模型加载路径与并发下的显存占用（来源同上）。
