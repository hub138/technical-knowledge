# 学习与迭代方法

过去的笔记主要按课程和时间堆积。现在改成按“真实问题 -> 机制理解 -> 证据 -> 练习 -> 迁移”组织。

## 每周循环

1. 选一个真实问题，写下要解释、预测或完成的结果。
2. 从主题页、官方文档、论文和代码中找证据。
3. 先做预测，再做最小实验或复现。
4. 用自己的话解释机制，记录反例和失败边界。
5. 把方法迁移到相邻场景，确认不是只记住原题。
6. 将新证据合并回主题页，并按错误和主题变化安排复习。

这套循环服务于知识增长，不是单独的“个人成长”分类：每次学习都必须落到一个技术主题、一个可验证问题或一个可复用产物。

## 课程资料的正确用法

课程 PDF、视频和源码是参考材料，不是需要全部重读的任务。先从主题索引进入，只有遇到具体问题时才回溯对应章节；读完后必须产出自己的结论、反例或实验记录。

## 当前优先级

- AI 系统：既理解模型、上下文、RAG 与 Agent，也理解推理后端、GPU/CPU 资源、分布式服务、平台、安全和评测；入口是 [[工程知识/AI系统/AI系统工程：把模型能力变成生产能力]]。
- 后端与分布式系统：掌握请求、任务和消息在并发、超时、重试、重复与部分失败下的语义；入口是 [[工程知识/后端与分布式系统/后端系统：在并发、失败与变化中维持服务]]。
- 数据系统：把查询、索引、事务、日志、复制与恢复看成共同维护事实的机制；入口是 [[工程知识/数据系统/数据系统：在并发与故障中保存事实]]。
- 计算机系统与性能：从用户 SLO 沿 trace、profile 和指标定位 CPU、GPU、内存、存储与网络瓶颈；入口是 [[工程知识/计算机系统与性能/性能工程：从用户等待到资源瓶颈]]。
- 软件构建与质量：用架构、代码、运行时、测试和发布证据让变化可理解、可验证、可回滚；入口是 [[工程知识/软件构建与质量/软件构建：让变化可以理解、验证与交付]]。
