# 设计语言：高亮语义、排序真源、token

## 高亮两套语义（不可混淆）

| 语义 | 样式 | 规则来源 |
|---|---|---|
| **当前位置** | 实底框：accent-soft 底 + accent-line 边 + accent-ink 字 + 左 3px 竖条 + semibold | aria-current（路由决定） |
| **站长推荐** | 暖橙项：warm-soft 底 + warm-line 边 + warm-ink 字，常驻亮着 | nav.js 条目 `pinned: true` |

- 钉选项被访问时两态叠加（观感一致），语义自洽。
- 实底框语义神圣：只回答「你在哪」，不挪用（挪用一次 = 导航定位报废）。
- 钉选项当前值：知识全景。换推荐对象 = 改 nav.js 的 `pinned` 所在条目。

## 音量原则

引导元素**颜色与位置一起设计**：颜色对但埋没 = 没用；位置对但刺眼 = 反感。音量降到所在容器级别（导航项级，非大卡）。

历史：琥珀大黄卡（引流有效但过重）→ 安静小行（无引导力）→ accent+★（过弱）→ 实底框常驻（位置混淆）→ **暖橙导航项 ✅**。

## 策展机制

- 时效雷达文章：frontmatter `type: radar`。
- 导航钉选：nav.js `pinned: true`。
- 铁律：阅读数据只进中台，不驱动展示。

## 排序真源

领域顺序（当前缺陷分析第一，余按篇数降序）两处消费同一规则，注释互指：

1. server `/api/domains`：`pinned = ("缺陷分析：从个案到体系",)` 钉首。
2. index.html：`PINNED_FIRST = ['总览','缺陷分析：…']`（领域卡/地形/阅读目录）+ `order` 数组同序。

## 颜色 token

| 用途 | 推荐位（暖） | 当前态（accent） |
|---|---|---|
| 底 | `--color-warm-soft` | `--color-accent-soft` |
| 边 | `--color-warm-line` | `--color-accent-line` |
| 字 | `--color-warm-ink` | `--color-accent-ink` |
| 强调条/图标 | `--color-warm` | `--color-accent` |

深浅主题走 token 自适应，禁止写死色值（历史教训：写死白描边深色主题刺眼）；SVG 描边用 currentColor。

## 文案规则（文案即产品）

- 面向读者写，不面向站长/过程写。反例：「别人做得更好的地方」「调研的好处」——这些是过程，读者不看。
- 抓眼球优于问答式：读者不带问题来。反例：「每一篇都回答这四个问题」→ 正解方向：怎么把知识快速装进读者脑子。
- 站长原话里的口语不入页面；站内标语自己总结提炼。
- 重复审查：所有面板/区块的文案写完当读者读一遍，幼稚表达全换。

## 布局规则

- 右侧空间必须利用：悬浮元素、入口、目录、刷新按钮都有位置。
- 删元素必补位：删掉一个区块后重新设计布局，不留空洞。
- 对齐强迫症：子级与父级、列与列、图标与文字，逐项截图核对。
- 信息密度：无用的英文小字（SOURCES · 外部资源 之类）、无意义横线、占位不展示的区块全删。
- 太空 = 布局错：缩小 div、重排，不是只删元素。

## 站长视觉偏好（硬规则，勿逆）

- **覆盖矩阵 = 全站最好的展示面**：象限 + 分类，优化最久，站长认可。
  它是「知识全景」页的**默认 tab**，不要改成别的。
- **八层栈气泡图被站长判为「丑」**：只在显式 `tab=stack` 时展示，
  不要主动推为默认、不要拿它当"最强展示面"来引导访客。
- 判断视觉好坏以站长的评价为准，不以"信息量大/酷炫"自行排序。
