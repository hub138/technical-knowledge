# 状态、动效与反馈

入口：做 hover/focus/当前项/禁用、加载空错态、动效时读。

## 五态必须齐

| 态 | 要求 |
|---|---|
| 默认 | 层级正确，不靠 hover 才看得懂 |
| hover | 有可见反馈 + `cursor: pointer`；过渡 150–300ms |
| focus | 键盘可达且有可见描边，不能只给鼠标做（ui-ux-pro-max 交付清单） |
| 当前（current） | 用 `aria-current`，视觉上实底框/左竖条/字重，回答"你在哪" |
| disabled | 明确变浅且不可点，不要只有颜色变化 |

- hover 不要做会推动布局的位移（scale 位移、边框突然加粗都算），只改颜色/阴影/透明度（ui-ux-pro-max `Stable hover states`）。
- 触屏上没有 hover，主要交互必须能点，不能只挂在 `mouseenter`（同库 `Hover vs Tap`）。

## 当前态与推荐态是两套语义

- 当前位置：路由决定，实底框，语义神圣，不挪用。
- 推荐/钉选：人工指定，暖色项，常驻亮着。
- 两者叠加时观感要自洽（访问钉选项时两态并存，不许互相吞掉）。
- 语义由结构决定（路由、人工标记），**不由数据决定**：阅读量/热度不驱动展示。

## 动效

- 动效服务于"变化被看见"，不服务于炫技；找不到理由就不加——这是一切动效判断的起点，先过这条再谈具体条款。
- 时长 150–300ms；超过 500ms 让人不耐烦（frontend-design 动效章）。
- 必须有 `prefers-reduced-motion` 分支。
- **reduce 分支拦不住 JS 发起的滚动**：CSS 里的 `animation-duration/transition-duration/scroll-behavior: auto` 只管 CSS 动画，`scrollIntoView/scrollTo` 显式传的 `behavior:'smooth'` 照跑——晕动症用户开了系统开关仍要陪跑整段滚动动画（实测：reduce 模式下 200ms 时页面还在动画中途）。全局滚动行为必须走一个查询点：`const smoothOK=!matchMedia('(prefers-reduced-motion: reduce)').matches`，所有 JS 滚动传 `behavior: smoothOK?'smooth':'auto'`，禁止散写硬编码 `'smooth'`（实测修后：reduce 模式 200ms 内一次跳达落点，normal 模式平滑在途，落点与焦点行为不变）。**判定线索**：grep 全站 `behavior:` 硬编码字符串，凡 JS 文件或内联脚本里出现的都要收编进查询点；CSS 写了 reduce 分支不代表滚动受控，两边要分开核对。
- 入场动画错峰用 `animation-delay`，别让所有元素一起动。
- 逐字弹入、逐行飞入这类纯装饰入场动效：先给整体淡入（150–300ms）的克制替代，把选择权交给用户；用户点名坚持才照做，照做时压进 300ms、给 `prefers-reduced-motion` 降级，且不得延误阅读起点。

## 加载 / 空 / 错误

- 超过 300ms 的操作必须有反馈（骨架屏或 spinner），不许界面冻住（ui-ux-pro-max `Loading Indicators`）。
- 异步内容预留尺寸（aspect-ratio 或固定高度），不许加载完把版面顶开（同库 `Content Jumping`）。
- 空态要有说明 + 一个动作，不许留白屏（同库 `Empty States`）。**说明写"这里以后会有什么"**，不写"暂无 XX"这种状态复读——「还没有操作记录，第一次操作后会出现在这里」是合格线，「暂无操作日志」不合格：读者需要的是预期，不是现状陈述。
- 错误信息必须带下一步怎么办；视觉之外要有 `role="alert"` 或 `aria-live`（同库 `Error Feedback` / `Error Messages`）。

## 性能是设计的一部分（本项目实测教训）

首屏速度直接决定访客去留，以下三类浪费在美化审查时一并列出，与像素问题同级对待：

- **没人消费的数据不拉**：启动链路里每个请求都要能在渲染产物里指出它画到了哪里；指不出来就删（实测：49KB 的接口拉回全站无人读，还附带一次整页重建）。
- **重建不重拉**：渲染函数会被路由、轮询、语言切换反复调用；函数内的取数必须有缓存挡门，重建只重画不重取（实测：`no-store` 接口在每次重建时真拉，一次停留传了三遍 79KB）。
- **轮询无事不做**：定时刷新先比签名，数据没变就不动界面（实测：每 10 秒把首页 innerHTML 连同 SVG 推倒重建一次，肉眼可见闪烁）。
- 验收用资源清单说话：页面加载列出每个请求的字节数与次数，重复请求与无人消费的请求都是违规项。

## 无障碍底线

- 图片有 alt；表单有 label；颜色不是唯一信号；键盘能走完全流程。
- **核心资产在键盘路径里排第一**：Tab 顺序按文档序，不按视觉序——侧栏写在 `main` 之前时，`main` 里的跳转链接第一步仍会先走侧栏（最小复现证实）。键盘用户到达正文的第一步必须 ≤ 2 步（实测：文章页 Tab 25 步才到正文，修后 1 步），量法是 Tab 步进记录首个落在正文容器内的元素序号。标准解法是 skip link（`<body>` 开头、默认移出屏幕、聚焦现身），目标容器加 `tabindex="-1"`——不加它回车后焦点弹回 `<body>`，跳转等于没跳（实测踩过）。
- **页内锚点跳转必须给目标标题留 `scroll-margin-top`**：固定/吸顶栏占着视口上沿，`scrollIntoView({block:'start'})` 与 hash 导航都把目标顶到视口最顶，标题正好停在栏下缘被盖住——修前实测落点 `top=0` 低于顶栏高 69px，属于"盖住"形态的动态版本，静态载入看不出、点一次目录立刻现形。值 = 栏高 + 一档区块级呼吸（16px，修后实测落点 86px）。**写在目标标题元素上，不写在 `:target` 伪类上**：目录点击常走 `preventDefault` + `scrollIntoView`，不产生 `:target`，元素级 `scroll-margin-top` 两类跳转都生效（实测踩过）。自查同源线索：同页 scrollspy 的 `rootMargin` 已经按顶栏占位算过补偿量、跳转处却没同步处理，两处逻辑矛盾就是缺陷信号。
- **程序触发的跳转必须把焦点随迁到目标**：目录/锚点点击后焦点仍留在触发链接上，键盘用户按 Tab 会跳回目录区而不是正文，跳转只发生了视觉没有发生交互。目标元素缺 `tabindex` 时补 `-1` 再 `focus({preventScroll:true})`（`preventScroll` 避免二次滚动与平滑滚动打架，实测一次到位）。
- **视图切换/隐藏触发链路的末端必须归还焦点**：点击隐藏的按钮（返回目录后工具组 `hidden`）会把焦点摔到 `<body>`，键盘用户从文件开头重新走一遍 Tab。分支终点都要接住：回列表聚焦列表入口、回首页聚焦品牌链接、回搜索聚焦搜索框（实测：返回按钮三分支中两分支焦点落空，修后三个分支各有明确落点）。
- **当前态必须恰好标记一个元素，且失效代码会自我暴露**：当前态的标准载体是 `aria-current`（读屏与视觉同源）。两类翻车都发生过：一是样式挂在永远没人赋值的选择器上（`.radar-card[aria-current="page"]` 写了样式、全站无一处赋值——遇到 `[aria-current]` 样式先 grep 赋值点，查不到就是失效样式）；二是同一语义多套载体（一个组件用 `.active` 类、另一个用 `aria-current`，视觉一样读屏漏报）。同一层级的当前态只留一个载体，赋值统一收在渲染入口处，不散在增强闭包里——闭包只在构造时跑一次，路由切换后不刷新，实测域行标记停在上一次的域上。**载体统一不等于取值统一**：`page` 与 `location` 是读屏语义不同的两档——`page` 报"这是另一个页面"，是导航 landmark 快捷键的跳转目标；`location` 报"当前位置在这"。滚动驱动的位置标注（目录 scrollspy、同屏多段高亮）必须用 `location`，用 `page` 会让读屏快捷键把滚动位置当页面切换误导航（实测修前 TOC 标 `page`、修后 `location`，样式选择器与视觉不变）；整页路由的导航项才用 `page`。
- **关掉焦点环必须同时给出等价替代，"等价"以键盘用户拿到的信息量计**：`.node:focus{outline:none}` 这类写法常见的辩护是"圆点套方框丑"，问题在替代物是否真的覆盖了焦点承担的信息职责。判定动作：聚焦该元素，量三样——焦点视觉标记（outline/描边/阴影至少其一可见）、悬停反馈的键盘等价物是否挂上（`onmouseenter` 独占的探索反馈对键盘不存在，要 `focusin/focusout` 挂同一函数）、状态属性（`aria-pressed` 等）与可聚焦性匹配。三样缺一就是净失去（实测：图谱 449 个可 Tab 节点聚焦后 outline:none、31 条邻线高亮只有鼠标有、键盘零反馈；修后悬停与聚焦共用一个点亮函数，键盘拿到与鼠标同一套反馈）。
- **状态会变的控件，可访问名称必须跟着状态走**：折叠钮点击后 `aria-expanded` 与箭头变了、`aria-label` 若还停在初始动作，读屏听到的动作与实际相反（收起后仍念"折叠"）。修法不是散着重赋——把"按当前态 + 当前语言重算名称"收敛成一个同步函数，状态变化与语言切换两个事件都调它（实测：折叠钮三处状态源一次收敛）。同时注意可访问名称是拼接串的情况：词典按整串匹配，`${动词}${名词}` 拼出来的串永远不命中，必须按语言分支拼装，两段各自走词典。
- **"疑似 hover 缺陷"先查语义再动手**：量到"hover 无反馈"不一定是缺陷——当前位置项与 hover 共用一条规则、静态卡有意不响应 hover（静态卡动效会许诺不存在的交互），都是设计决定。判定口径：拿走 hover 后信息还全不全；全，就是有意静默。别把「无变化」直接记成翻车。
- 状态变化同步进 URL，支持深链（同库 `Deep Linking`）。
